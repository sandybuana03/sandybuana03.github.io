Pengenalan Debugging

🤖 Apa itu Debugging?

Debugging adalah proses menemukan, menganalisis, dan memperbaiki kesalahan (bug) dalam program komputer. Istilah "bug" pertama kali digunakan oleh Grace Hopper pada tahun 1947 ketika ia menemukan seekor ngengat yang terjebak dalam komputer!

💡 Fun Fact: Bug pertama dalam sejarah komputer adalah benar-benar seekor serangga (ngengat) yang menyebabkan komputer Harvard Mark II error!

🎯 Mengapa Debugging Penting?

Untuk Programmer:

  • • Meningkatkan kualitas kode
  • • Menghemat waktu development
  • • Meningkatkan skill problem solving
  • • Memahami kode lebih dalam

Untuk Pengguna:

  • • Aplikasi berjalan lancar
  • • Pengalaman pengguna yang baik
  • • Keamanan data terjaga
  • • Performa aplikasi optimal

Konsep Dasar Debugging

🐛 Apa itu Bug?

Bug adalah kesalahan, cacat, atau kegagalan dalam program komputer yang menyebabkan hasil yang tidak diinginkan atau perilaku yang tidak benar.

Syntax Error

Kesalahan penulisan kode

Logic Error

Kesalahan logika program

Runtime Error

Error saat program berjalan

🧠 Mindset Debugging

✅ Yang Harus Dilakukan:

  • • Tetap tenang dan sabar
  • • Berpikir sistematis
  • • Dokumentasikan proses
  • • Belajar dari setiap bug
  • • Minta bantuan jika perlu

❌ Yang Harus Dihindari:

  • • Panik atau frustrasi
  • • Menebak-nebak solusi
  • • Mengabaikan error message
  • • Tidak testing setelah fix
  • • Menyalahkan tools/compiler

🔍 Prinsip Debugging

1. Reproduce the Bug

Pastikan kamu bisa membuat bug terjadi lagi secara konsisten

2. Isolate the Problem

Temukan bagian kode mana yang menyebabkan masalah

3. Understand the Root Cause

Pahami mengapa bug tersebut terjadi

4. Fix and Verify

Perbaiki bug dan pastikan tidak ada efek samping

Jenis-jenis Error

🔴 Syntax Error

Error yang terjadi karena penulisan kode yang tidak sesuai dengan aturan bahasa pemrograman.

Contoh Syntax Error:

// Error: Missing semicolon
let name = "John"
console.log(name)

// Error: Missing closing bracket
if (x > 5) {
  console.log("Greater than 5")
// Missing }

Cara Mengatasi:

  • • Perhatikan pesan error dari compiler/interpreter
  • • Gunakan code editor dengan syntax highlighting
  • • Periksa tanda kurung, titik koma, dan tanda kutip

🟠 Runtime Error

Error yang terjadi saat program sedang berjalan, meskipun syntax-nya benar.

Contoh Runtime Error:

// Error: Division by zero
let result = 10 / 0;

// Error: Accessing undefined property
let user = null;
console.log(user.name); // Cannot read property 'name' of null

Cara Mengatasi:

  • • Gunakan try-catch untuk menangani error
  • • Validasi input sebelum diproses
  • • Periksa nilai null/undefined sebelum digunakan

🟡 Logic Error

Error yang paling sulit ditemukan. Program berjalan tanpa crash, tapi hasilnya salah.

Contoh Logic Error:

// Error: Wrong condition (should be <=)
for (let i = 0; i < 10; i++) {
  console.log(i); // Only prints 0-9, not 0-10
}

// Error: Wrong calculation
let average = (a + b + c) / 2; // Should be divided by 3

Cara Mengatasi:

  • • Gunakan debugger untuk step-by-step execution
  • • Tambahkan console.log untuk tracking nilai
  • • Review logika program dengan teliti
  • • Buat test case untuk berbagai skenario

🎮 Demo Interaktif: Temukan Error!

Coba temukan dan perbaiki error dalam kode berikut:

function calculateArea(length, width) {
  let area = length * width
  return area
}

let result = calculateArea(5, 3)
console.log("Area is: " + result

Error ditemukan:

  • • Baris 2: Missing semicolon setelah 'width'
  • • Baris 6: Missing closing parenthesis

Kode yang sudah diperbaiki:

function calculateArea(length, width) {
  let area = length * width;
  return area;
}

let result = calculateArea(5, 3);
console.log("Area is: " + result);

Teknik Debugging

🖨️ Print/Console Debugging

Teknik paling sederhana dan sering digunakan. Menambahkan output untuk melihat nilai variabel dan alur program.

Contoh Penggunaan:

function processData(data) {
  console.log("Input data:", data);
  
  let processed = data.map(item => {
    console.log("Processing item:", item);
    return item * 2;
  });
  
  console.log("Result:", processed);
  return processed;
}

✅ Kelebihan:

  • • Mudah dan cepat
  • • Tidak perlu tools khusus
  • • Bisa digunakan di semua bahasa

❌ Kekurangan:

  • • Bisa membuat kode berantakan
  • • Harus dihapus setelah debugging
  • • Tidak efisien untuk bug kompleks

🦆 Rubber Duck Debugging

Teknik menjelaskan masalah secara detail kepada objek (seperti bebek karet) untuk membantu menemukan solusi.

Cara Melakukan:

  1. 1. Siapkan "bebek karet" (bisa objek apapun atau bahkan bayangan)
  2. 2. Jelaskan masalah kamu secara detail kepada "bebek"
  3. 3. Jelaskan apa yang seharusnya terjadi vs apa yang terjadi
  4. 4. Jelaskan setiap baris kode yang relevan
  5. 5. Sering kali solusi akan muncul saat menjelaskan!

💡 "Dalam proses menjelaskan masalah kepada bebek, kamu akan sering menemukan jawabannya sendiri!"

🔍 Binary Search Debugging

Teknik membagi kode menjadi dua bagian untuk menemukan di mana bug berada, mirip dengan binary search.

Langkah-langkah:

1

Tentukan titik awal dan akhir di mana bug mungkin berada

2

Tambahkan checkpoint di tengah-tengah

3

Jalankan program dan lihat apakah bug terjadi sebelum atau sesudah checkpoint

4

Fokus pada bagian yang bermasalah dan ulangi proses

🎮 Demo: Simulasi Debugging

Mari simulasikan proses debugging dengan contoh sederhana:

function findMax(numbers) {
  let max = 0; // 🐛 Potential bug here!
  for (let i = 0; i < numbers.length; i++) {
    if (numbers[i] > max) {
      max = numbers[i];
    }
  }
  return max;
}

Step 1: Test dengan input [-5, -2, -10]

Expected: -2, Actual: 0 ❌

Step 2: Analisis - max diinisialisasi dengan 0

Semua angka negatif tidak akan lebih besar dari 0!

Step 3: Solusi - Inisialisasi max dengan elemen pertama

let max = numbers[0]; ✅

Praktik Debugging

🔍 Case Study: Calculator Bug

Sebuah kalkulator sederhana tidak memberikan hasil yang benar. Mari kita debug bersama!

Kode Bermasalah:

function calculator(a, b, operation) {
  switch(operation) {
    case 'add':
      return a + b;
    case 'subtract':
      return a - b;
    case 'multiply':
      return a * b;
    case 'divide':
      return a / b;
  }
}

// Test cases
console.log(calculator("5", "3", "add")); // Expected: 8, Actual: 53

🐛 Masalah yang Ditemukan:

  • • Parameter berupa string, bukan number
  • • Tidak ada default case
  • • Tidak ada validasi input

✅ Solusi:

  • • Convert string ke number
  • • Tambahkan default case
  • • Validasi input dan operation

Kode yang Sudah Diperbaiki:

function calculator(a, b, operation) {
  // Convert to numbers
  const numA = parseFloat(a);
  const numB = parseFloat(b);
  
  // Validate inputs
  if (isNaN(numA) || isNaN(numB)) {
    return "Error: Invalid numbers";
  }
  
  switch(operation) {
    case 'add':
      return numA + numB;
    case 'subtract':
      return numA - numB;
    case 'multiply':
      return numA * numB;
    case 'divide':
      if (numB === 0) return "Error: Division by zero";
      return numA / numB;
    default:
      return "Error: Invalid operation";
  }
}

🎮 Latihan Interaktif: Debug Array Function

Coba debug function berikut yang seharusnya mengembalikan angka terbesar dalam array:

function findLargest(arr) {
  let largest = 0;
  for (let i = 1; i <= arr.length; i++) {
    if (arr[i] > largest) {
      largest = arr[i];
    }
  }
  return largest;
}

Test Results:

Bug 1: largest diinisialisasi dengan 0

Jika semua angka negatif, hasilnya akan salah!

Bug 2: Loop dimulai dari index 1

Elemen pertama (index 0) tidak pernah dicek!

Bug 3: Kondisi i <= arr.length

Akan mengakses index yang tidak ada (undefined)!

Kode yang Diperbaiki:

function findLargest(arr) {
  if (arr.length === 0) return undefined;
  let largest = arr[0]; // Start with first element
  for (let i = 1; i < arr.length; i++) { // Start from index 1, use <
    if (arr[i] > largest) {
      largest = arr[i];
    }
  }
  return largest;
}

💡 Tips Debugging Praktis

🎯 Sebelum Debugging:

  • • Pahami apa yang seharusnya terjadi
  • • Kumpulkan informasi error lengkap
  • • Reproduksi bug secara konsisten

🔍 Saat Debugging:

  • • Mulai dari yang sederhana
  • • Jangan asumsikan, selalu verifikasi
  • • Dokumentasikan temuan

✅ Setelah Fix:

  • • Test fix secara menyeluruh
  • • Pastikan tidak ada regression
  • • Belajar dari bug tersebut

🚫 Hindari:

  • • Mengubah banyak hal sekaligus
  • • Mengandalkan keberuntungan
  • • Skip testing setelah fix

Tugas Debugging

Kerjakan tugas berikut untuk menguji pemahaman kalian tentang debugging

📋 Soal 1: Analisis Error

Perhatikan kode JavaScript berikut yang mengalami error. Identifikasi jenis error dan jelaskan cara memperbaikinya:

function calculateDiscount(price, discountPercent) {
  let discount = price * discountPercent / 100
  let finalPrice = price - discount
  return finalPrice
}

let result = calculateDiscount("100", "20")
console.log("Final price: " + result

Pertanyaan:

  1. a) Sebutkan minimal 3 error yang ada dalam kode tersebut!
  2. b) Klasifikasikan setiap error (Syntax Error, Runtime Error, atau Logic Error)!
  3. c) Tuliskan kode yang sudah diperbaiki!
  4. d) Jelaskan mengapa error tersebut terjadi!

🔍 Soal 2: Strategi Debugging

Kalian diminta untuk debug sebuah aplikasi web yang mengalami masalah. Aplikasi tersebut seharusnya menampilkan daftar produk, tetapi halaman menjadi blank (kosong).

Informasi yang diketahui:

  • • Aplikasi menggunakan JavaScript untuk fetch data dari API
  • • Sebelumnya aplikasi berjalan normal
  • • Tidak ada error message yang terlihat di halaman
  • • API endpoint masih bisa diakses langsung via browser

Pertanyaan:

  1. a) Sebutkan 5 langkah debugging yang akan kalian lakukan secara berurutan!
  2. b) Tools apa saja yang akan kalian gunakan untuk debugging masalah ini?
  3. c) Sebutkan 3 kemungkinan penyebab masalah dan cara mengeceknya!
  4. d) Bagaimana cara kalian memastikan fix yang dilakukan tidak menimbulkan masalah baru?

💻 Soal 3: Praktik Debugging

Buatlah sebuah function sederhana yang mengandung bug, kemudian jelaskan proses debugging-nya!

Tugas:

  1. a) Buat function JavaScript yang memiliki minimal 2 jenis error berbeda
  2. b) Jelaskan apa yang seharusnya dilakukan function tersebut
  3. c) Identifikasi dan jelaskan setiap error yang ada
  4. d) Perbaiki function tersebut dan jelaskan proses debugging yang kalian lakukan
  5. e) Berikan test case untuk membuktikan function sudah benar
