Langkah 1: Pemeriksaan Fisik

Mulai dari yang bisa dilihat mata!

🔍

Mengapa Mulai dari Pemeriksaan Fisik?

70% masalah jaringan disebabkan oleh masalah fisik yang sederhana seperti kabel longgar atau LED mati. Ini mengikuti prinsip "Layer 1 OSI Model" - Physical Layer!

🔌 Kabel & Koneksi:

  • • Kabel jaringan terpasang kencang
  • • Tidak ada kerusakan fisik kabel
  • • Port RJ45 tidak longgar
  • • Kabel tidak tertekuk berlebihan
  • • Panjang kabel < 100 meter

💡 LED Indikator:

  • • 🟢 Hijau solid = Link established
  • • 🟡 Kuning berkedip = Data activity
  • • 🔴 Merah = Error/collision
  • • ⚫ Mati = No physical connection
  • • 🟠 Orange = 10/100 Mbps mode

⚡ Power & Hardware:

  • • Power adapter tersambung
  • • Switch/router menyala
  • • Network card terdeteksi
  • • Tidak ada overheating
  • • Port tidak rusak fisik

Jenis-jenis Kabel Jaringan

🔗 Kabel UTP (Unshielded Twisted Pair)

Cat 5e: Up to 1 Gbps, 100 MHz

Cat 6: Up to 1 Gbps, 250 MHz

Cat 6a: Up to 10 Gbps, 500 MHz

Straight-through: PC ke Switch

Crossover: PC ke PC (jarang digunakan)

🔍 Cara Cek Kabel Rusak

  • • Visual: cek fisik kabel
  • • Ganti dengan kabel lain
  • • Gunakan cable tester
  • • Cek continuity dengan multimeter
  • • Test di port berbeda

Simulasi Pemeriksaan Fisik

💻

🔌

📡

✅ Physical Layer Check: PASSED

Semua komponen fisik berfungsi normal. Lanjut ke Layer 3 (Network)!

Troubleshooting Fisik Lanjutan

🔧 Tools yang Dibutuhkan

  • • Cable Tester: Test kontinuitas kabel
  • • Multimeter: Cek voltage & resistance
  • • Crimping Tool: Buat kabel baru
  • • Kabel Cadangan: Untuk replacement test
  • • Flashlight: Periksa port gelap

⚠️ Common Physical Issues

  • • Loose Connection: Kabel tidak terpasang kencang
  • • Cable Damage: Kabel putus atau tertekuk
  • • Wrong Port: Salah port atau disabled
  • • Power Issue: Switch/router mati
  • • Duplex Mismatch: Speed/duplex tidak cocok

Checklist Pemeriksaan Fisik

✅ Hardware Check:

  • □ Network adapter terdeteksi di Device Manager
  • □ Driver network adapter ter-install
  • □ LED link menyala di network card
  • □ LED activity berkedip saat ada traffic
  • □ Port switch/router tidak rusak

✅ Cable Check:

  • □ Kabel terpasang kencang di kedua ujung
  • □ Tidak ada kerusakan fisik pada kabel
  • □ Panjang kabel tidak melebihi 100m
  • □ Menggunakan jenis kabel yang tepat
  • □ Test dengan kabel cadangan

Langkah 2: Cek Konfigurasi IP

Pastikan komputer punya "alamat" yang benar!

🏠

Mengapa Harus Cek IP Address?

IP Address seperti alamat rumah di internet. Tanpa alamat yang benar, komputer tidak bisa "ditemukan" oleh jaringan! Ini adalah Layer 3 (Network Layer) dari model OSI.

Anatomi IP Address

IPv4 Address Structure
192.168.1.100
Network: 192.168.1
Host: 100
Class: C (Private)
Subnet Mask
255.255.255.0
CIDR: /24
Network bits: 24
Host bits: 8

Command IPCONFIG Variations

# Basic IP info
C:\> ipconfig
# Detailed info
C:\> ipconfig /all
# Release IP
C:\> ipconfig /release
# Renew IP
C:\> ipconfig /renew

✅ IP Normal:

  • • 192.168.1.xxx (Class C Private)
  • • 192.168.0.xxx (Class C Private)
  • • 10.0.0.xxx (Class A Private)
  • • 172.16-31.xxx (Class B Private)
  • • Ada Gateway & DNS Server

❌ IP Bermasalah:

  • • 169.254.xxx.xxx (APIPA)
  • • 0.0.0.0 (No IP assigned)
  • • Tidak ada Default Gateway
  • • Subnet mask salah
  • • DNS Server kosong

🔍 Yang Harus Dicek:

  • • IP Address valid
  • • Subnet Mask sesuai
  • • Default Gateway ada
  • • DNS Server configured
  • • DHCP Client running

DHCP vs Static IP Configuration

🔄 DHCP (Dynamic)

IP address diberikan otomatis oleh DHCP server:

  • • Pros: Mudah, otomatis, no conflict
  • • Cons: IP bisa berubah
  • • Cocok untuk: Client workstation
  • • Lease time: Biasanya 24 jam
  • • Renewal: Otomatis di 50% lease

📌 Static IP

IP address dikonfigurasi manual:

  • • Pros: IP tetap, predictable
  • • Cons: Manual config, risk conflict
  • • Cocok untuk: Server, printer
  • • Requirement: Unique dalam subnet
  • • Management: Manual tracking

Troubleshooting IP Issues

🔧 APIPA Problem (169.254.x.x)

Automatic Private IP Addressing - terjadi ketika DHCP server tidak dapat dihubungi:

  1. Cek koneksi fisik ke DHCP server
  2. Restart DHCP Client service
  3. Release & renew IP: ipconfig /release && ipconfig /renew
  4. Flush DNS cache: ipconfig /flushdns
  5. Restart network adapter

🔧 IP Conflict Resolution

Ketika dua device menggunakan IP yang sama:

  1. Identifikasi device yang conflict
  2. Release IP dari salah satu device
  3. Renew IP atau set static IP berbeda
  4. Update DHCP reservation jika perlu
  5. Monitor dengan arp -a

🔧 Advanced IP Commands

# Show routing table
route print
# Show ARP table
arp -a
# Reset TCP/IP stack
netsh int ip reset
# Reset Winsock
netsh winsock reset

Langkah 3: Test Ping

Tes konektivitas dengan "mengetuk pintu" jaringan!

🏓

Apa itu PING?

PING (Packet Internet Groper) menggunakan protokol ICMP untuk mengirim Echo Request ke target dan menunggu Echo Reply. Seperti mengetuk pintu rumah tetangga untuk memastikan mereka ada di rumah!

Urutan Test PING Sistematis

1
PING Localhost (127.0.0.1)

Test TCP/IP stack komputer sendiri - memastikan protokol jaringan berfungsi

💻
2
PING IP Address Sendiri

Test network adapter dan driver - memastikan hardware berfungsi

🔌
3
PING Default Gateway

Test koneksi ke router/switch - memastikan koneksi lokal

📡
4
PING DNS Server (8.8.8.8)

Test koneksi ke internet - memastikan routing berfungsi

🌐
5
PING Domain Name (google.com)

Test DNS resolution - memastikan name resolution berfungsi

🔍

✅ PING Berhasil:

  • • Reply from [IP Address]
  • • Time < 100ms (LAN), < 300ms (WAN)
  • • 0% packet loss
  • • TTL (Time To Live) normal
  • • Consistent response times

❌ PING Gagal:

  • • Request timeout
  • • Destination host unreachable
  • • 100% packet loss
  • • General failure
  • • TTL expired in transit

Variasi Command PING

# Basic ping (4 packets)
ping 8.8.8.8
# Continuous ping
ping -t 8.8.8.8
# Ping with count
ping -n 10 8.8.8.8
# Ping with size
ping -l 1024 8.8.8.8
C:\> ping 8.8.8.8

Interpretasi Hasil PING

📊 Parameter Penting

  • • Time: Latency/delay (ms)
  • • TTL: Time To Live (hops)
  • • Bytes: Packet size
  • • Loss: Packet loss percentage
  • • Statistics: Min/Max/Average

🔍 Troubleshooting Tips

  • • High latency (>100ms): Network congestion
  • • Packet loss: Faulty hardware/cable
  • • Timeout: Firewall/routing issue
  • • Unreachable: No route to destination
  • • Inconsistent times: Network instability

Advanced PING Techniques

🔧 Pathping Command

Kombinasi ping dan tracert untuk analisis mendalam:

pathping google.com

🔧 Tracert Command

Melacak rute paket dari source ke destination:

tracert google.com

Langkah 4: Cek DNS

Pastikan "penerjemah" nama website bekerja!

Apa itu DNS?

DNS (Domain Name System) adalah sistem hierarkis yang menerjemahkan nama domain yang mudah diingat (google.com) menjadi alamat IP yang dimengerti komputer (142.250.190.78). Seperti buku telepon internet yang menghubungkan nama dengan nomor!

  • • Malware protection

✅ DNS Normal:

  • • Website bisa dibuka dengan nama domain
  • • NSLOOKUP mengembalikan IP address
  • • Ping domain name berhasil
  • • Response time < 100ms
  • • No timeout errors

❌ DNS Bermasalah:

  • • Website tidak bisa dibuka dengan nama
  • • Ping IP berhasil, ping domain gagal
  • • Error "DNS server not responding"
  • • NSLOOKUP timeout atau error
  • • Slow DNS resolution (>1000ms)

DNS Troubleshooting Commands

🔍 NSLOOKUP Command

# Basic lookup
nslookup google.com
# Specify DNS server

🔧 DNS Cache Commands

📊 Interpretasi Output NSLOOKUP

  • • Server: DNS server yang digunakan untuk query
  • • Address: IP address DNS server
  • • Non-authoritative: Hasil dari cache, bukan server asli
  • • Name: Domain name yang di-query
  • • Addresses: IP address hasil resolusi (IPv4 & IPv6)

DNS Troubleshooting Steps

🔧 Langkah Troubleshooting DNS

  1. Test basic connectivity: ping 8.8.8.8 (pastikan internet OK)
  2. Test DNS resolution: nslookup google.com
  3. Flush DNS cache: ipconfig /flushdns
  4. Try different DNS server: nslookup google.com 1.1.1.1
  5. Check DNS configuration: ipconfig /all (lihat DNS servers)
  6. Change DNS server: Set manual DNS (8.8.8.8, 1.1.1.1)
  7. Restart DNS Client service: services.msc → DNS Client

⚠️ Common DNS Issues

  • • DNS server down: ISP DNS bermasalah
  • • DNS cache poisoning: Cache corrupt
  • • Wrong DNS config: DNS server salah
  • • Firewall blocking: Port 53 blocked
  • • DNS hijacking: Malware redirect
  • • Network congestion: Slow response

Langkah 5: Reset & Restart

Solusi terakhir yang sering berhasil!

🔄

Mengapa Reset & Restart?

Restart membersihkan cache, reset konfigurasi sementara, dan memulai ulang semua service jaringan. Seperti "tidur" untuk menyegarkan pikiran!

Urutan Reset yang Benar

1
Restart Network Adapter

Disable → Enable network adapter

🔌
2
Restart Komputer

Restart untuk refresh semua service

💻
3
Restart Router/Modem

Cabut power 30 detik, pasang kembali

📡

🎯 Kapan Restart?

  • • Setelah 4 langkah sebelumnya gagal
  • • Koneksi tiba-tiba hilang
  • • Setelah install software baru
  • • Performa jaringan menurun

⚠️ Tips Restart:

  • • Tunggu 30 detik sebelum nyalakan
  • • Restart router dulu, baru komputer
  • • Catat konfigurasi sebelum reset
  • • Test koneksi setelah restart

Command Reset Network

# Reset TCP/IP Stack
netsh int ip reset
# Reset Winsock
netsh winsock reset
# Flush DNS Cache
ipconfig /flushdns
# Release & Renew IP
ipconfig /release
ipconfig /renew
# Reset Network Adapter
netsh interface set interface "Ethernet" disable
netsh interface set interface "Ethernet" enable

⚠️ Penting: Jalankan Command Prompt sebagai Administrator untuk command ini.

Setelah menjalankan netsh commands, restart komputer untuk memastikan perubahan diterapkan sepenuhnya.
