Pengenalan Version Control

🤷‍♂️ Apa itu Version Control System?

Version Control System (VCS) adalah sistem yang mencatat setiap perubahan pada file atau kumpulan file dari waktu ke waktu. Bayangkan seperti "history" di browser, tapi untuk kode program!

Analogi Sederhana:

VCS seperti buku diary yang mencatat semua perubahan kode. Setiap kali kamu mengubah kode, VCS akan "mengingat" apa yang berubah, kapan, dan siapa yang mengubahnya.

🎯 Mengapa Perlu VCS?

🔒

Backup Otomatis

Kode tersimpan aman, tidak akan hilang

👥

Kerja Tim

Banyak orang bisa edit kode bersamaan

⏰

History Lengkap

Bisa lihat semua perubahan dari awal

🔄

Rollback

Bisa kembali ke versi sebelumnya

📊 Contoh Tanpa vs Dengan VCS

❌ Tanpa VCS

  • • File: project_final.zip
  • • File: project_final_v2.zip
  • • File: project_final_REAL.zip
  • • File: project_final_REAL_v3.zip
  • 😵 Bingung mana yang terbaru!

✅ Dengan VCS

  • • Satu folder: project/
  • • History otomatis tersimpan
  • • Bisa lihat siapa mengubah apa
  • • Bisa kembali ke versi manapun
  • 😊 Rapi dan terorganisir!

Apa itu Git?

🚀 Definisi Git

Git adalah salah satu VCS yang paling populer di dunia! Dibuat oleh Linus Torvalds (pembuat Linux) pada tahun 2005. Git gratis, cepat, dan sangat powerful!

💡 Fun Fact:

Nama "Git" berasal dari bahasa slang Inggris yang artinya "orang bodoh". Linus Torvalds bilang dia suka memberi nama proyeknya dengan namanya sendiri! 😄

⭐ Keunggulan Git

⚡

Super Cepat

Operasi lokal, tidak perlu internet

🌐

Distributed

Setiap komputer punya copy lengkap

🔀

Branching

Bisa buat cabang untuk fitur baru

🏗️ Konsep Dasar Git

📁 Repository (Repo)

Folder project yang dikelola Git. Seperti "rumah" untuk kode-mu!

📸 Commit

Seperti "foto" dari kondisi kode pada waktu tertentu. Setiap commit punya pesan yang menjelaskan apa yang berubah.

🌿 Branch

Cabang pengembangan. Branch utama biasanya bernama "main" atau "master".

Git Commit

📸 Apa itu Commit?

Commit adalah seperti "checkpoint" dalam game! Setiap kali kamu commit, Git akan menyimpan "foto" dari semua file pada saat itu. Jika ada masalah, kamu bisa kembali ke checkpoint ini.

🎮 Analogi Game:

Bayangkan kamu main game RPG. Sebelum melawan boss, kamu save game dulu kan? Nah, commit itu seperti save game untuk kode program!

🔄 Proses Commit

1️⃣

Working Directory

File yang kamu edit (belum di-track Git)

git status → "modified: index.html"
2️⃣

Staging Area (Index)

Area persiapan sebelum commit - seperti "keranjang belanja" untuk perubahan

git add index.html

💡 Bisa add/remove file sebelum commit

3️⃣

Repository

File yang sudah tersimpan permanen di Git

git commit -m "Update homepage"

✍️ Cara Menulis Commit Message yang Baik

❌ Contoh Buruk

"fix"
"update"
"asdfgh"
"final final final"

✅ Contoh Baik

"Add login form validation"
"Fix navbar responsive issue"
"Update homepage design"
"Remove unused CSS files"

Tips Commit Message:

  • • Gunakan bahasa Inggris (standar industri)
  • • Mulai dengan kata kerja: Add, Fix, Update, Remove
  • • Maksimal 50 karakter untuk judul
  • • Jelaskan APA yang berubah, bukan BAGAIMANA

Git Push & Pull

☁️ Remote Repository

Remote repository adalah "rumah" kode di internet (seperti GitHub, GitLab). Di sini kode tersimpan aman dan bisa diakses dari mana saja!

💻 Local Repository

Git di komputer kamu

  • • Bisa kerja offline
  • • Cepat akses
  • • Hanya kamu yang bisa akses

🌐 Remote Repository

Git di server (GitHub)

  • • Backup aman
  • • Tim bisa akses
  • • Bisa akses dari mana saja

📤 Git Push

Push = "dorong" commit dari local ke remote. Seperti upload file, tapi lebih canggih!

Perintah Push:

# Push ke branch main
git push origin main
# Push pertama kali (set upstream)
git push -u origin main

💡 Kapan Harus Push?

  • • Setelah menyelesaikan fitur
  • • Sebelum pulang kerja/sekolah
  • • Setelah fix bug penting
  • • Minimal 1x sehari (good practice)

📥 Git Pull

Pull = "tarik" update terbaru dari remote ke local. Seperti download update, tapi otomatis merge!

Perintah Pull:

# Pull dari branch main
git pull origin main
# Pull dengan rebase (lebih bersih)
git pull --rebase origin main
# Fetch dulu, lalu merge manual
git fetch origin
git merge origin/main

🔍 Perbedaan Fetch vs Pull

git fetch:
  • • Download info terbaru
  • • Tidak mengubah file lokal
  • • Aman untuk cek update
git pull:
  • • Fetch + merge sekaligus
  • • Langsung update file lokal
  • • Bisa ada conflict

⚠️ Kapan Harus Pull?

  • • Sebelum mulai coding
  • • Sebelum push (untuk avoid conflict)
  • • Ketika ada update dari tim
  • • Setelah lama tidak coding

Tugas Praktik

Saatnya praktik langsung! 💪

🎯 Tugas 1: Setup Git

Langkah-langkah:

  1. 1. Install Git di komputer kamu (download dari git-scm.com)
  2. 2. Buka Command Prompt atau Terminal
  3. 3. Set konfigurasi nama dan email:
git config --global user.name "Nama Lengkap Kamu"
git config --global user.email "email@kamu.com"
Jawab pertanyaan ini:

📁 Tugas 2: Membuat Repository

Langkah-langkah:

  1. 1. Buat folder baru bernama "project-git-saya"
  2. 2. Masuk ke folder tersebut di terminal
  3. 3. Jalankan perintah git init
  4. 4. Buat file README.md dengan isi perkenalan diri
  5. 5. Cek status dengan git status
Jawab pertanyaan ini:

💾 Tugas 3: Commit Pertama

Langkah-langkah:

  1. 1. Add file README.md: git add README.md
  2. 2. Commit dengan pesan yang jelas: git commit -m "Add initial README file"
  3. 3. Lihat history commit: git log --oneline
  4. 4. Buat file index.html sederhana
  5. 5. Add dan commit file baru tersebut
Jawab pertanyaan ini:

🌐 Tugas 4: GitHub Integration

Langkah-langkah:

  1. 1. Buat akun GitHub (jika belum punya)
  2. 2. Buat repository baru di GitHub dengan nama "project-git-saya"
  3. 3. Connect local repo ke GitHub:
# Tambahkan remote origin
git remote add origin https://github.com/username/project-git-saya.git
# Rename branch ke main (jika perlu)
git branch -M main
# Push pertama kali
git push -u origin main
  1. 4. Buat perubahan di file, commit, dan push lagi
  2. 5. Coba edit file langsung di GitHub, lalu pull ke local
  3. 6. Praktikkan workflow: pull → edit → commit → push
⚠️ Tips Penting:
  • • Pastikan branch name sama (main/master)
  • • Jika error, cek apakah repo GitHub kosong atau sudah ada README
  • • Gunakan HTTPS URL untuk kemudahan (tidak perlu SSH key)
