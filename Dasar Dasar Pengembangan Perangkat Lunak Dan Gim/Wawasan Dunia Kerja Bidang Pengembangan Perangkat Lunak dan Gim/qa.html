Pengenalan Quality Assurance

🔍 Apa itu Quality Assurance (QA)?

Quality Assurance (QA) adalah serangkaian aktivitas yang dirancang untuk memastikan bahwa proses pengembangan perangkat lunak menghasilkan produk berkualitas tinggi. QA berfokus pada pencegahan cacat melalui perbaikan proses, sedangkan Testing berfokus pada deteksi cacat dalam produk yang sudah jadi.

🔍 QA vs Testing:
QA (Quality Assurance):
  • • Pencegahan cacat
  • • Fokus pada proses
  • • Proaktif
Testing:
  • • Deteksi cacat
  • • Fokus pada produk
  • • Reaktif

Analogi Sederhana:

Bayangkan QA seperti seorang chef yang mencicipi masakan sebelum disajikan ke pelanggan. Mereka memastikan rasa, tekstur, dan presentasi sudah sempurna! 👨‍🍳

✅ Mengapa QA Penting?

  • • Mencegah bug yang merugikan pengguna
  • • Menghemat biaya perbaikan di masa depan
  • • Meningkatkan kepuasan pengguna
  • • Menjaga reputasi perusahaan

👥 Siapa Saja Tim QA?

  • • Test Lead/Manager
  • • Automation Engineer

1. Prevention over Detection

Lebih baik mencegah bug daripada mencari bug setelah terjadi

2. Customer Focus

Selalu mengutamakan kepuasan dan kebutuhan pengguna

3. Total Employee Involvement

Semua anggota tim bertanggung jawab atas kualitas

4. Process Approach

Menggunakan pendekatan sistematis dan terstruktur

5. Continuous Improvement

Selalu berusaha meningkatkan proses dan kualitas

Keputusan berdasarkan data dan fakta, bukan asumsi

🎭 Berdasarkan Teknik Testing

⚫ Black Box Testing

Testing tanpa melihat kode internal, fokus pada input dan output.

Contoh: Menguji login dengan username/password yang benar dan salah

⚪ White Box Testing

Testing dengan melihat dan memahami kode internal program.

Contoh: Menguji setiap baris kode dalam fungsi perhitungan

🔘 Gray Box Testing

Kombinasi Black Box dan White Box, dengan pengetahuan terbatas tentang kode.

Contoh: Integration testing dengan akses ke dokumentasi API

📝 Membuat Test Case yang Baik

Komponen Test Case:

• Test Case ID: Identifikasi unik
• Test Description: Deskripsi singkat
• Preconditions: Kondisi awal
• Test Steps: Langkah-langkah
• Expected Result: Hasil yang diharapkan
• Actual Result: Hasil aktual
Contoh Test Case:

ID: TC_LOGIN_001

Description: Verify login with valid credentials

Preconditions: User has valid account

Steps: 1. Enter username 2. Enter password 3. Click login

Expected: User successfully logged in

🐛 Bug Life Cycle

Bug Life Cycle adalah tahapan yang dilalui sebuah bug dari ditemukan hingga diselesaikan. Setiap tahap memiliki peran dan tanggung jawab yang jelas.

🆕

1. New

Bug baru ditemukan dan dilaporkan oleh QA tester. Status awal setelah bug report dibuat.

Penanggung jawab: QA Tester

↓
📋

2. Assigned

Bug telah ditinjau dan ditugaskan kepada developer untuk diperbaiki.

Penanggung jawab: Project Manager/Lead Developer

↓
🔧

3. In Progress

Developer sedang aktif mengerjakan perbaikan bug. Proses coding dan debugging berlangsung.

Penanggung jawab: Developer

↓
✅

4. Fixed

Developer telah selesai memperbaiki bug dan siap untuk diuji ulang (retesting).

Penanggung jawab: Developer → QA Tester

↓
🔍

5. Retesting

QA melakukan pengujian ulang untuk memverifikasi bahwa bug sudah benar-benar teratasi.

Penanggung jawab: QA Tester

↓
🔒

6. Closed

Bug telah berhasil diperbaiki dan diverifikasi. Tidak ada masalah lebih lanjut.

Penanggung jawab: QA Tester

💡 Status Tambahan yang Mungkin Terjadi:

🔄 Reopened: Bug muncul kembali setelah diperbaiki

❌ Rejected: Bug report ditolak karena bukan bug sebenarnya

📋 Duplicate: Bug sudah pernah dilaporkan sebelumnya

⏸️ Deferred: Bug ditunda untuk versi selanjutnya
