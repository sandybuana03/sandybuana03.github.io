Jenis-jenis Error

💥 1. Syntax Error

Error yang terjadi karena penulisan kode yang salah. Seperti salah ketik atau lupa tanda kurung.

Contoh:

// Salah - kurang tanda kurung tutup
System.out.println("Hello World";

// Benar
System.out.println("Hello World");

⚡ 2. Runtime Error

Error yang terjadi saat program berjalan. Program bisa di-compile tapi error saat dijalankan.

Contoh:

// Error: ArrayIndexOutOfBoundsException
int[] arr = {1, 2, 3};
System.out.println(arr[5]); // Error!

// Error: NullPointerException
String str = null;
System.out.println(str.length()); // Error!

🧠 3. Logic Error

Program berjalan tanpa error, tapi hasilnya salah karena logika yang keliru.

Contoh:

// Salah - seharusnya penjumlahan
int total = harga1 - harga2;

// Benar
int total = harga1 + harga2;

Try-Catch Statement

🛡️ Apa itu Try-Catch?

Try-catch adalah struktur kontrol yang memungkinkan kita untuk "mencoba" menjalankan kode yang mungkin error, dan "menangkap" error tersebut jika terjadi.

Struktur Dasar:

try {
// Kode yang mungkin error
} catch (Exception e) {
// Kode untuk menangani error
} finally {
// Kode yang selalu dijalankan (opsional)
}

📝 Contoh Penggunaan

Contoh 1: Membaca File

try {
Scanner scanner = new Scanner(new File("data.txt"));
String content = scanner.nextLine();
System.out.println("File berhasil dibaca: " + content);
scanner.close();
} catch (FileNotFoundException e) {
System.out.println("Error: File tidak ditemukan!");
}

Contoh 2: Pembagian dengan Validasi

public static double bagi(double a, double b) {
try {
// Validasi input
if (b == 0) {
throw new ArithmeticException("Tidak bisa bagi dengan nol!");
}
return a / b;
} catch (ArithmeticException e) {
System.err.println("Error: " + e.getMessage());
// Return nilai default
return Double.NaN;
}
}

// Contoh penggunaan:
System.out.println(bagi(10, 2)); // Output: 5.0
System.out.println(bagi(10, 0)); // Output: NaN + pesan error

🔄 Multiple Catch Blocks

Java memungkinkan kita menangkap berbagai jenis exception dengan multiple catch blocks:

try {
int[] arr = {1, 2, 3};
int result = arr[5] / 0;
} catch (ArrayIndexOutOfBoundsException e) {
System.err.println("Error: Index array tidak valid!");
} catch (ArithmeticException e) {
System.err.println("Error: Pembagian dengan nol!");
} catch (Exception e) {
System.err.println("Error umum: " + e.getMessage());
}

💡 Tips Penting

✅

DO (Lakukan)

  • • Tangkap error yang spesifik
  • • Berikan pesan error yang jelas
  • • Log error untuk debugging
  • • Berikan fallback/alternatif
  • • Validasi input sebelum proses
❌

DON'T (Jangan)

  • • Mengabaikan error begitu saja
  • • Catch semua error tanpa handling
  • • Memberikan pesan error yang membingungkan
  • • Menggunakan try-catch untuk flow control
  • • Expose informasi sensitif dalam error

Teknik Debugging

🔍 Apa itu Debugging?

Debugging adalah proses mencari dan memperbaiki bug (kesalahan) dalam program. Seperti detektif yang mencari petunjuk untuk memecahkan kasus! 🕵️‍♂️

Langkah-langkah Debugging:

  1. 1Identifikasi masalah
  2. 2Reproduksi error
  3. 3Analisis kode
  4. 4Perbaiki bug
  5. 5Test solusi

🔧 Kode yang Diperbaiki:

public static double hitungRataRata(int[] numbers) {
if (numbers == null || numbers.length == 0) {
throw new IllegalArgumentException("Array kosong atau null!");
}
int total = 0;
for (int i = 0; i < numbers.length; i++) { // Perbaikan: i < bukan i <=
total += numbers[i];
}
return (double) total / numbers.length;
}

Best Practices Error Handling

✅ 1. Berikan Pesan Error yang Jelas

❌Buruk

throw new Exception("Error!");

✅Baik

throw new IllegalArgumentException("Email tidak valid. Harap masukkan format email yang benar.");

🎯 2. Tangkap Error yang Spesifik

❌Buruk

try {
// semua kode
} catch (Exception e) {
// tangkap semua error
}

✅Baik

try {
int result = Integer.parseInt(data);
} catch (NumberFormatException e) {
// handle parsing error
} catch (Exception e) {
// handle other errors
}

🛡️ 3. Validasi Input

Selalu validasi input sebelum memproses untuk mencegah error.

public static double hitungLuasSegitiga(double alas, double tinggi) {
// Validasi input
if (Double.isNaN(alas) || Double.isNaN(tinggi)) {
throw new IllegalArgumentException("Alas dan tinggi harus berupa angka");
}
if (alas <= 0 || tinggi <= 0) {
throw new IllegalArgumentException("Alas dan tinggi harus lebih dari 0");
}
return 0.5 * alas * tinggi;
}

📝 4. Log Error untuk Debugging

try {
// kode yang mungkin error
} catch (Exception e) {
// Log untuk developer
System.err.println("Error detail: " + e.getMessage());
e.printStackTrace();
// Pesan untuk user
System.out.println("Terjadi kesalahan. Silakan coba lagi.");
}

🔄 5. Berikan Fallback/Alternatif

Sediakan solusi alternatif ketika terjadi error.

public static User ambilDataUser(int id) {
try {
return database.getUser(id);
} catch (SQLException e) {
System.err.println("Gagal ambil data user: " + e.getMessage());
// Fallback: return data default
return new User(id, "User Tidak Dikenal", "");
}
}

🏷️ 6. Custom Error Types

Buat tipe error khusus untuk kasus yang spesifik.

// Membuat custom exception class
class ValidationException extends Exception {
public ValidationException(String message) {
super(message);
}
}

// Penggunaan custom exception
public static void validasiEmail(String email) throws ValidationException {
if (!email.contains("@")) {
throw new ValidationException("Format email tidak valid");
}
}

// Menangkap custom exception
try {
validasiEmail("user-email");
} catch (ValidationException e) {
System.out.println("Error validasi: " + e.getMessage());
}
