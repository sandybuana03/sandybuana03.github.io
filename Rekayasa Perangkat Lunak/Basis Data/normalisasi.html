Perancangan Basis Data & Normalisasi

🏗️

Perancangan Basis Data

Perancangan Basis Data adalah proses merancang struktur database yang efisien, konsisten, dan mudah dikelola. Seperti arsitek yang merancang rumah, kita perlu merencanakan bagaimana data akan disimpan dan diorganisir.

📋 Tahapan Perancangan:
  • • Analisis kebutuhan data
  • • Perancangan konseptual (ERD)
  • • Perancangan logikal
  • • Normalisasi Database
  • • Implementasi fisik
🎯 Tujuan Perancangan:
  • • Menghindari duplikasi data
  • • Menjaga konsistensi data
  • • Memudahkan maintenance
  • • Meningkatkan performa
  • • Menghemat storage
🔧

Apa itu Normalisasi?

Normalisasi adalah teknik dalam perancangan database untuk mengorganisir data dengan cara mengurangi redundansi dan meningkatkan integritas data. Ini adalah bagian penting dari perancangan basis data yang baik!

Definisi Formal: Normalisasi adalah proses dekomposisi tabel yang memiliki anomali untuk menghasilkan tabel-tabel yang lebih kecil dan terdefinisi dengan baik, serta bebas dari anomali.

⚠️ Masalah Tanpa Normalisasi:

😵

Data Redundan

Data yang berulang-ulang

Contoh: Nama siswa "Andi" muncul di 10 baris berbeda
🔄

Update Anomaly

Susah mengubah data

Contoh: Ubah nama "Andi" harus di 10 tempat sekaligus
🗑️

Delete Anomaly

Data hilang saat dihapus

Contoh: Hapus siswa terakhir, info jurusan ikut hilang
📊

Bentuk-bentuk Normal (Normal Forms)

Normalisasi memiliki beberapa tingkatan yang disebut "Normal Forms". Setiap tingkat memiliki aturan yang semakin ketat:

1️⃣ First Normal Form (1NF)

Setiap kolom berisi nilai tunggal (atomic)

2️⃣ Second Normal Form (2NF)

1NF + tidak ada partial dependency

3️⃣ Third Normal Form (3NF)

2NF + tidak ada transitive dependency

💡 Tips: Sebagian besar database dalam dunia nyata menggunakan 3NF karena memberikan keseimbangan yang baik antara efisiensi storage dan performa query.

💡

Analogi Sederhana: Merapikan Perpustakaan 📚

❌ Sebelum Normalisasi:

Seperti perpustakaan yang berantakan:

  • • Buku yang sama ada di banyak rak
  • • Info penulis ditulis berulang-ulang
  • • Susah cari dan update data buku
  • • Boros tempat dan membingungkan
✅ Setelah Normalisasi:

Seperti perpustakaan yang rapi:

  • • Setiap buku punya tempat yang tepat
  • • Info penuler disimpan terpisah
  • • Mudah cari, update, dan kelola
  • • Hemat tempat dan terorganisir
🤷‍♂️

Kapan Menggunakan Normalisasi?

✅ Gunakan Normalisasi Ketika:
  • • Database untuk aplikasi transaksional (OLTP)
  • • Banyak operasi INSERT, UPDATE, DELETE
  • • Konsistensi data sangat penting
  • • Storage terbatas
  • • Data sering berubah
⚠️ Pertimbangkan Denormalisasi Ketika:
  • • Database untuk reporting (OLAP)
  • • Lebih banyak operasi SELECT
  • • Performa query lebih penting
  • • Data jarang berubah
  • • Kompleksitas query tinggi

1️⃣

First Normal Form (1NF)

Aturan 1NF:

  • ✅ Setiap kolom hanya boleh berisi satu nilai (atomic)
  • ✅ Tidak ada nilai yang berulang dalam satu kolom
  • ✅ Setiap baris harus unik

❌ Sebelum 1NF (Tidak Normal):

ID_Siswa Nama Hobi Telepon
001 Andi Baca, Musik, Game 081234, 087654
002 Budi Olahraga, Masak 085555

⚠️ Masalah: Satu kolom berisi banyak nilai!

✅ Setelah 1NF (Normal):

ID_Siswa Nama Hobi Telepon
001 Andi Baca 081234
001 Andi Musik 087654
001 Andi Game 081234
002 Budi Olahraga 085555

✨ Sekarang setiap kolom hanya berisi satu nilai!

2️⃣

Second Normal Form (2NF)

Aturan 2NF:

  • ✅ Sudah memenuhi 1NF
  • ✅ Tidak ada partial dependency
  • ✅ Semua atribut non-key bergantung penuh pada primary key
🔑

Apa itu Partial Dependency?

Ketika ada atribut yang hanya bergantung pada sebagian dari primary key (bukan keseluruhan). Ini terjadi kalau primary key terdiri dari beberapa kolom (composite key).

❌ Sebelum 2NF:

ID_Siswa (PK) ID_Mapel (PK) Nama_Siswa Nama_Mapel Nilai
001 M01 Andi Matematika 85
001 M02 Andi Fisika 90

⚠️ Masalah: Nama_Siswa hanya bergantung pada ID_Siswa, Nama_Mapel hanya bergantung pada ID_Mapel!

✅ Setelah 2NF (Dipecah jadi 3 tabel):

Tabel Siswa:
ID_Siswa (PK) Nama_Siswa
001 Andi
Tabel Mata Pelajaran:
ID_Mapel (PK) Nama_Mapel
M01 Matematika
M02 Fisika
Tabel Nilai:
ID_Siswa (FK) ID_Mapel (FK) Nilai
001 M01 85
001 M02 90

✨ Sekarang tidak ada partial dependency!

A. Ketika primary key hanya satu kolom

3️⃣

Third Normal Form (3NF)

Aturan 3NF:

  • ✅ Sudah memenuhi 2NF
  • ✅ Tidak ada transitive dependency
  • ✅ Atribut non-key tidak bergantung pada atribut non-key lain
🔄

Apa itu Transitive Dependency?

Ketika atribut A bergantung pada B, dan B bergantung pada C, maka A secara tidak langsung bergantung pada C.

A → B → C

Contoh: ID_Siswa → Kode_Jurusan → Nama_Jurusan

❌ Sebelum 3NF:

ID_Siswa (PK) Nama_Siswa Kode_Jurusan Nama_Jurusan Kepala_Jurusan
001 Andi RPL Rekayasa Perangkat Lunak Pak Budi
002 Sari RPL Rekayasa Perangkat Lunak Pak Budi

⚠️ Masalah: Nama_Jurusan dan Kepala_Jurusan bergantung pada Kode_Jurusan, bukan ID_Siswa!

✅ Setelah 3NF (Dipecah jadi 2 tabel):

Tabel Siswa:
ID_Siswa (PK) Nama_Siswa Kode_Jurusan (FK)
001 Andi RPL
002 Sari RPL
Tabel Jurusan:
Kode_Jurusan (PK) Nama_Jurusan Kepala_Jurusan
RPL Rekayasa Perangkat Lunak Pak Budi

✨ Sekarang tidak ada transitive dependency!

🧠 Quiz 3NF:

A. ID_Siswa → Kode_Kelas → Nama_Kelas
B. ID_Siswa → Nama_Siswa
C. ID_Siswa → Alamat_Siswa

Rangkuman Normalisasi

1️⃣

1NF

  • ✅ Satu kolom = satu nilai
  • ✅ Tidak ada nilai berulang
  • ✅ Setiap baris unik
2️⃣

2NF

  • ✅ Sudah 1NF
  • ✅ Tidak ada partial dependency
  • ✅ Semua atribut bergantung penuh pada PK
3️⃣

3NF

  • ✅ Sudah 2NF
  • ✅ Tidak ada transitive dependency
  • ✅ Atribut non-key tidak saling bergantung

🌟 Manfaat Normalisasi:

💾 Menghemat ruang penyimpanan
🔄 Mudah update data
🛡️ Menghindari data inconsistent
⚡ Performa database lebih baik
