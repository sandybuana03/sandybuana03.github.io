Pengenalan Normalisasi

🤖 Apa itu Normalisasi?

Normalisasi adalah proses mengorganisir data dalam basis data untuk mengurangi redundansi (pengulangan data) dan meningkatkan integritas data.

💡 Bayangkan seperti merapikan buku di perpustakaan - setiap buku punya tempat yang tepat!

🎯 Mengapa Normalisasi Penting?

✅ Keuntungan:

  • • Mengurangi duplikasi data (redundansi)
  • • Menghemat ruang penyimpanan
  • • Mempermudah update data
  • • Mengurangi anomali data (insert, update, delete)
  • • Meningkatkan integritas data
  • • Struktur database lebih fleksibel

❌ Tanpa Normalisasi:

  • • Data berulang-ulang (redundansi)
  • • Boros ruang penyimpanan
  • • Sulit update data konsisten
  • • Inkonsistensi data
  • • Anomali insert (data tidak lengkap)
  • • Anomali delete (kehilangan data penting)

🎉 Normalisasi 3NF Selesai!

  • • ✅ Memenuhi 1NF: Nilai atomik, baris unik, ada PK
  • • ✅ Memenuhi 2NF: Tidak ada partial dependency
  • • ✅ Memenuhi 3NF: Tidak ada transitive dependency

🔗 Konsep Functional Dependency

Apa itu Functional Dependency?

Functional Dependency (FD) adalah hubungan antara atribut dimana nilai dari satu atribut menentukan nilai atribut lainnya.

Notasi: A → B (dibaca: A menentukan B)

Artinya: Jika kita tahu nilai A, maka kita bisa menentukan nilai B secara unik

Contoh FD:

  • • NIM → Nama_Mahasiswa
  • • Kode_Barang → Nama_Barang
  • • ID_Karyawan → Nama_Karyawan
  • • Plat_Nomor → Pemilik_Mobil

Jenis FD:

  • • Full FD: Bergantung pada seluruh key
  • • Partial FD: Bergantung pada sebagian key
  • • Transitive FD: Bergantung tidak langsung

🎉 Normalisasi 3NF Selesai!

  • • ✅ Memenuhi 1NF: Nilai atomik, baris unik, ada PK
  • • ✅ Memenuhi 2NF: Tidak ada partial dependency
  • • ✅ Memenuhi 3NF: Tidak ada transitive dependency

📊 Contoh Sederhana

Mari lihat contoh tabel siswa yang belum dinormalisasi:

ID Siswa Nama Siswa Kelas Wali Kelas Mata Pelajaran Nilai
001 Andi XII RPL 1 Bu Sari Basis Data 85
001 Andi XII RPL 1 Bu Sari Pemrograman Web 90
002 Budi XII RPL 1 Bu Sari Basis Data 78

🚨 Masalah yang terlihat:

  • • Redundansi: Data siswa dan kelas berulang
  • • Boros storage: Tempat penyimpanan tidak efisien
  • • Update Anomaly: Jika wali kelas berubah, harus update banyak baris
  • • Insert Anomaly: Tidak bisa input kelas tanpa ada siswa
  • • Delete Anomaly: Jika siswa terakhir dihapus, data kelas ikut hilang
1️⃣

First Normal Form (1NF)

📋 Aturan 1NF

1. Setiap kolom harus berisi nilai atomik (tidak dapat dibagi lagi)

Tidak boleh ada nilai yang berisi beberapa data sekaligus

2. Setiap baris harus unik

Tidak boleh ada baris yang persis sama

3. Harus ada primary key

Setiap baris harus bisa diidentifikasi secara unik

🎉 Normalisasi 3NF Selesai!

  • • ✅ Memenuhi 1NF: Nilai atomik, baris unik, ada PK
  • • ✅ Memenuhi 2NF: Tidak ada partial dependency
  • • ✅ Memenuhi 3NF: Tidak ada transitive dependency

❌ Contoh Tabel yang TIDAK memenuhi 1NF

ID Siswa Nama Hobi No. Telepon
001 Andi Membaca, Gaming, Coding 081234567890, 087654321098
002 Budi Olahraga, Musik 082345678901

🚨 Masalah:

Kolom "Hobi" dan "No. Telepon" berisi beberapa nilai sekaligus (tidak atomik)

✅ Setelah dinormalisasi ke 1NF

Tabel Siswa:

ID Siswa (PK) Nama
001 Andi
002 Budi

Tabel Hobi:

ID Siswa (FK) Hobi
001 Membaca
001 Gaming
001 Coding
002 Olahraga
002 Musik

Tabel Telepon:

ID Siswa (FK) No. Telepon
001 081234567890
001 087654321098
002 082345678901

✅ Sekarang sudah memenuhi 1NF:

  • • Setiap kolom berisi nilai atomik
  • • Setiap baris unik
  • • Ada primary key dan foreign key

🎮 Demo Interaktif 1NF

Coba identifikasi masalah pada tabel ini:

ID Nama Produk Kategori
P001 Laptop Gaming Elektronik, Gaming, Komputer

Masalah: Kolom "Kategori" tidak atomik (berisi 3 nilai sekaligus)

Solusi: Pisahkan menjadi tabel terpisah untuk kategori

🎉 Normalisasi 3NF Selesai!

  • • ✅ Memenuhi 1NF: Nilai atomik, baris unik, ada PK
  • • ✅ Memenuhi 2NF: Tidak ada partial dependency
  • • ✅ Memenuhi 3NF: Tidak ada transitive dependency
2️⃣

Second Normal Form (2NF)

📋 Aturan 2NF

1. Harus sudah memenuhi 1NF

Semua aturan 1NF harus terpenuhi terlebih dahulu

2. Tidak ada partial dependency

Semua atribut non-key harus bergantung penuh pada seluruh primary key (berlaku untuk composite key)

💡 Partial Dependency adalah:

Ketika atribut non-key hanya bergantung pada sebagian dari composite primary key, bukan pada keseluruhan key

Catatan: Jika tabel hanya memiliki single primary key (bukan composite), maka otomatis sudah memenuhi 2NF

❌ Contoh Tabel yang TIDAK memenuhi 2NF

ID Siswa (PK) Kode Mapel (PK) Nama Siswa Nama Mapel Nilai
001 BD01 Andi Basis Data 85
001 PW01 Andi Pemrograman Web 90
002 BD01 Budi Basis Data 78

🚨 Masalah Partial Dependency:

  • • "Nama Siswa" hanya bergantung pada "ID Siswa" (bukan pada composite key)
  • • "Nama Mapel" hanya bergantung pada "Kode Mapel" (bukan pada composite key)
  • • Hanya "Nilai" yang bergantung pada kedua key

✅ Setelah dinormalisasi ke 2NF

Tabel Siswa:

ID Siswa (PK) Nama Siswa
001 Andi
002 Budi

Tabel Mata Pelajaran:

Kode Mapel (PK) Nama Mapel
BD01 Basis Data
PW01 Pemrograman Web

Tabel Nilai:

ID Siswa (PK, FK) Kode Mapel (PK, FK) Nilai
001 BD01 85
001 PW01 90
002 BD01 78

✅ Sekarang sudah memenuhi 2NF:

  • • Tidak ada partial dependency
  • • Setiap atribut bergantung penuh pada primary key
  • • Data lebih terorganisir dan efisien

🎮 Demo Interaktif 2NF

Identifikasi partial dependency pada tabel ini:

ID Order (PK) ID Produk (PK) Tanggal Order Nama Produk Jumlah
ORD001 P001 2024-01-15 Laptop 2

Partial Dependencies:

  • • "Tanggal Order" hanya bergantung pada "ID Order"
  • • "Nama Produk" hanya bergantung pada "ID Produk"
  • • Hanya "Jumlah" yang bergantung pada kedua key

🎉 Normalisasi 3NF Selesai!

  • • ✅ Memenuhi 1NF: Nilai atomik, baris unik, ada PK
  • • ✅ Memenuhi 2NF: Tidak ada partial dependency
  • • ✅ Memenuhi 3NF: Tidak ada transitive dependency
3️⃣

Third Normal Form (3NF)

📋 Aturan 3NF

1. Harus sudah memenuhi 2NF

Semua aturan 1NF dan 2NF harus terpenuhi

2. Tidak ada transitive dependency

Atribut non-key tidak boleh bergantung pada atribut non-key lainnya

💡 Transitive Dependency adalah:

Ketika A → B dan B → C, maka A → C (dependency tidak langsung melalui atribut perantara)

Contoh: ID_Siswa → Kode_Kelas → Wali_Kelas

❌ Contoh Tabel yang TIDAK memenuhi 3NF

ID Siswa (PK) Nama Siswa Kode Kelas Nama Kelas Wali Kelas
001 Andi XII-RPL-1 XII RPL 1 Bu Sari
002 Budi XII-RPL-1 XII RPL 1 Bu Sari
003 Citra XII-RPL-2 XII RPL 2 Pak Budi

🚨 Masalah Transitive Dependency:

  • • ID Siswa → Kode Kelas → Nama Kelas
  • • ID Siswa → Kode Kelas → Wali Kelas
  • • "Nama Kelas" dan "Wali Kelas" bergantung pada "Kode Kelas", bukan langsung pada primary key

✅ Setelah dinormalisasi ke 3NF

Tabel Siswa:

ID Siswa (PK) Nama Siswa Kode Kelas (FK)
001 Andi XII-RPL-1
002 Budi XII-RPL-1
003 Citra XII-RPL-2

Tabel Kelas:

Kode Kelas (PK) Nama Kelas Wali Kelas
XII-RPL-1 XII RPL 1 Bu Sari
XII-RPL-2 XII RPL 2 Pak Budi

✅ Sekarang sudah memenuhi 3NF:

  • • Tidak ada transitive dependency
  • • Setiap atribut non-key bergantung langsung pada primary key
  • • Data lebih efisien dan konsisten

📊 Ringkasan Normalisasi

1NF

  • • Nilai atomik
  • • Baris unik
  • • Ada primary key

2NF

  • • Memenuhi 1NF
  • • Tidak ada partial dependency
  • • Bergantung penuh pada PK

3NF

  • • Memenuhi 2NF
  • • Tidak ada transitive dependency
  • • Bergantung langsung pada PK

🎉 Normalisasi 3NF Selesai!

  • • ✅ Memenuhi 1NF: Nilai atomik, baris unik, ada PK
  • • ✅ Memenuhi 2NF: Tidak ada partial dependency
  • • ✅ Memenuhi 3NF: Tidak ada transitive dependency

K001 Ahmad IT IT Support Lantai 3

Transitive Dependencies:

  • • ID Karyawan → Kode Dept → Nama Dept
  • • ID Karyawan → Kode Dept → Lokasi Dept
  • • Solusi: Pisahkan tabel Departemen

  • • ✅ Memenuhi 2NF: Tidak ada partial dependency
  • • ✅ Memenuhi 3NF: Tidak ada transitive dependency

📄 create_tables.sql

-- Tabel Anggota (Entitas independen)
CREATE TABLE anggota (
    id_anggota VARCHAR(10) PRIMARY KEY,
    nama VARCHAR(100) NOT NULL,
    alamat TEXT,
    no_telepon VARCHAR(15)
);

-- Tabel Buku (Entitas independen)
CREATE TABLE buku (
    kode_buku VARCHAR(10) PRIMARY KEY,
    judul VARCHAR(200) NOT NULL,
    pengarang VARCHAR(100),
    penerbit VARCHAR(100),
    tahun_terbit YEAR,
    isbn VARCHAR(20)
);

-- Tabel Peminjaman (Entitas relasi)
CREATE TABLE peminjaman (
    id_peminjaman VARCHAR(10) PRIMARY KEY,
    tanggal_pinjam DATE NOT NULL,
    tanggal_kembali DATE,
    status ENUM('dipinjam', 'dikembalikan') DEFAULT 'dipinjam',
    id_anggota VARCHAR(10) NOT NULL,
    kode_buku VARCHAR(10) NOT NULL,
    FOREIGN KEY (id_anggota) REFERENCES anggota(id_anggota) 
        ON DELETE CASCADE ON UPDATE CASCADE,
    FOREIGN KEY (kode_buku) REFERENCES buku(kode_buku) 
        ON DELETE CASCADE ON UPDATE CASCADE
);

  4. Apakah ada transitive dependency? Jika ada, sebutkan!

🛠️ Soal 2: Praktik Normalisasi

Berdasarkan tabel pada Soal 1, lakukan normalisasi hingga 3NF!

Tugas:

  1. Buat struktur tabel yang memenuhi 1NF
  2. Lanjutkan normalisasi ke 2NF (hilangkan partial dependency)
  3. Selesaikan dengan normalisasi ke 3NF (hilangkan transitive dependency)
  4. Gambar ERD (Entity Relationship Diagram) dari hasil normalisasi
  5. Tulis SQL CREATE TABLE untuk semua tabel hasil normalisasi

  • Aplikasi read-heavy (lebih banyak baca daripada tulis)
