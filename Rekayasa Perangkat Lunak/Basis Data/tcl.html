Pengenalan TCL

Transaction Control Language

🤖 Apa itu TCL?

Transaction Control Language (TCL) adalah bagian dari SQL yang digunakan untuk mengontrol transaksi dalam database. TCL memungkinkan kita untuk mengelola perubahan data dengan aman dan terkontrol.

Analogi: Bayangkan TCL seperti sistem kontrol dalam video game. Kamu bisa menyimpan progress (COMMIT), kembali ke checkpoint terakhir (ROLLBACK), atau membuat checkpoint baru (SAVEPOINT)! 🎮

✅

COMMIT

Menyimpan semua perubahan secara permanen ke database

↩️

ROLLBACK

Membatalkan semua perubahan yang belum di-commit

📍

SAVEPOINT

Membuat titik checkpoint dalam transaksi

🏦 Contoh Kasus Nyata

Misalkan kamu sedang transfer uang dari rekening A ke rekening B:

1 Kurangi saldo rekening A sebesar Rp 100.000
2 Tambah saldo rekening B sebesar Rp 100.000
3 COMMIT - Simpan perubahan jika semua berhasil
? ROLLBACK - Batalkan semua jika ada yang gagal

🎯 Mengapa TCL Penting?

Keuntungan:

  • ✓ Menjaga konsistensi data
  • ✓ Memungkinkan recovery dari error
  • ✓ Kontrol yang lebih baik

Tanpa TCL:

  • ✗ Data bisa tidak konsisten
  • ✗ Sulit recovery dari error
  • ✗ Risiko kehilangan data
✅

COMMIT

Menyimpan Perubahan Secara Permanen

🎯 Apa itu COMMIT?

COMMIT adalah perintah yang digunakan untuk menyimpan semua perubahan yang telah dilakukan dalam transaksi secara permanen ke database. Setelah COMMIT dijalankan, perubahan tidak dapat dibatalkan lagi.

Analogi: COMMIT seperti menekan tombol "Save" pada dokumen. Setelah di-save, perubahan tersimpan permanen! 💾

📝 Sintaks COMMIT

COMMIT;

Sintaksnya sangat sederhana! Cukup tulis COMMIT; dan semua perubahan dalam transaksi akan disimpan permanen.

🔄 Cara Kerja COMMIT

1

Mulai Transaksi

Database mulai mencatat semua perubahan

2

Eksekusi Perintah SQL

INSERT, UPDATE, DELETE dijalankan

3

COMMIT Dijalankan

Semua perubahan disimpan permanen

💡 Contoh Penggunaan

-- Mulai transaksi
START TRANSACTION;

-- Insert data mahasiswa baru
INSERT INTO mahasiswa (nama, jurusan, angkatan) 
VALUES ('Budi', 'Teknik Informatika', 2024);

-- Update nilai mahasiswa
UPDATE nilai 
SET score = 85 
WHERE mahasiswa_id = 123;

-- Simpan semua perubahan
COMMIT;

Dalam contoh di atas, setelah COMMIT dijalankan, data mahasiswa baru dan update nilai akan tersimpan permanen di database.

✅ Kapan Menggunakan COMMIT

  • • Setelah serangkaian operasi berhasil
  • • Ketika yakin data sudah benar
  • • Di akhir transaksi yang sukses

⚠️ Hal yang Perlu Diperhatikan

  • • COMMIT tidak bisa dibatalkan
  • • Pastikan data sudah benar sebelum COMMIT
  • • Cek kembali sebelum menyimpan
↩️

ROLLBACK

Membatalkan Perubahan Transaksi

🔄 Apa itu ROLLBACK?

ROLLBACK adalah perintah yang digunakan untuk membatalkan semua perubahan yang telah dilakukan dalam transaksi yang belum di-commit. Ini seperti tombol "Undo" yang membatalkan semua perubahan.

Analogi: ROLLBACK seperti menekan Ctrl+Z berkali-kali sampai kembali ke kondisi awal sebelum ada perubahan! ↶

📝 Sintaks ROLLBACK

ROLLBACK;

Untuk membatalkan ke savepoint tertentu:

ROLLBACK TO nama_savepoint;

🔄 Cara Kerja ROLLBACK

1

Transaksi Berjalan

Beberapa operasi SQL telah dijalankan

2

Terjadi Error/Masalah

Ada kesalahan atau perubahan yang tidak diinginkan

3

ROLLBACK Dijalankan

Semua perubahan dibatalkan, kembali ke kondisi awal

💡 Contoh Penggunaan

-- Mulai transaksi
START TRANSACTION;

-- Hapus data mahasiswa
DELETE FROM mahasiswa 
WHERE angkatan = 2020;

-- Ups! Salah hapus data!
-- Batalkan semua perubahan
ROLLBACK;

-- Data mahasiswa kembali seperti semula

Dalam contoh di atas, setelah ROLLBACK dijalankan, data mahasiswa yang terhapus akan kembali seperti semula karena perubahan dibatalkan.

🎯 Contoh Kasus Transfer Uang

START TRANSACTION;

-- Kurangi saldo rekening A
UPDATE rekening 
SET saldo = saldo - 1000000 
WHERE no_rekening = 'A123';

-- Cek apakah saldo mencukupi
SELECT saldo FROM rekening 
WHERE no_rekening = 'A123';

-- Jika saldo negatif, batalkan transaksi
ROLLBACK;

-- Atau jika berhasil, lanjutkan...

✅ Kapan Menggunakan ROLLBACK

  • • Ketika terjadi error dalam transaksi
  • • Saat kondisi bisnis tidak terpenuhi
  • • Untuk membatalkan perubahan yang salah

🎯 Keuntungan ROLLBACK

  • • Melindungi integritas data
  • • Recovery dari kesalahan
  • • Kontrol yang lebih baik
📍

SAVEPOINT

Membuat Checkpoint dalam Transaksi

📍 Apa itu SAVEPOINT?

SAVEPOINT adalah fitur yang memungkinkan kita membuat titik checkpoint dalam transaksi. Dengan savepoint, kita bisa melakukan rollback hanya ke titik tertentu, bukan ke awal transaksi.

Analogi: SAVEPOINT seperti checkpoint dalam video game. Kamu bisa kembali ke checkpoint tertentu tanpa harus mulai dari awal! 🎮

📝 Sintaks SAVEPOINT

Membuat savepoint:

SAVEPOINT nama_savepoint;

Rollback ke savepoint:

ROLLBACK TO nama_savepoint;

Menghapus savepoint:

RELEASE SAVEPOINT nama_savepoint;

🔄 Cara Kerja SAVEPOINT

1

Mulai Transaksi

START TRANSACTION dijalankan

2

Buat Savepoint

SAVEPOINT checkpoint1 dibuat

3

Eksekusi Operasi

Jalankan beberapa SQL commands

4

Rollback ke Savepoint

Kembali ke checkpoint1 jika diperlukan

💡 Contoh Penggunaan Lengkap

START TRANSACTION;

-- Insert data mahasiswa
INSERT INTO mahasiswa (nama, jurusan) 
VALUES ('Andi', 'Teknik Informatika');

-- Buat savepoint setelah insert
SAVEPOINT after_insert;

-- Update data mahasiswa
UPDATE mahasiswa 
SET jurusan = 'Sistem Informasi' 
WHERE nama = 'Andi';

-- Buat savepoint lagi
SAVEPOINT after_update;

-- Delete data (misalnya salah)
DELETE FROM mahasiswa 
WHERE nama = 'Andi';

-- Ups! Rollback ke setelah update
ROLLBACK TO after_update;

-- Sekarang data Andi masih ada dengan jurusan terupdate
COMMIT;

Dalam contoh ini, kita bisa kembali ke titik setelah update tanpa kehilangan data insert dan update yang sudah benar.

🏦 Contoh Kasus Kompleks: Sistem Perbankan

START TRANSACTION;

-- Validasi rekening sumber
SELECT saldo FROM rekening WHERE no_rek = 'A123';

SAVEPOINT validasi_sumber;

-- Kurangi saldo rekening sumber
UPDATE rekening 
SET saldo = saldo - 500000 
WHERE no_rek = 'A123';

SAVEPOINT debit_sumber;

-- Validasi rekening tujuan
SELECT * FROM rekening WHERE no_rek = 'B456';

-- Jika rekening tujuan tidak ada
ROLLBACK TO debit_sumber;

-- Atau jika ada, lanjutkan
UPDATE rekening 
SET saldo = saldo + 500000 
WHERE no_rek = 'B456';

COMMIT;

✅ Keuntungan SAVEPOINT

  • • Kontrol yang lebih granular
  • • Tidak perlu rollback semua
  • • Efisiensi dalam error handling
  • • Fleksibilitas tinggi

💡 Tips Penggunaan

  • • Beri nama savepoint yang jelas
  • • Jangan terlalu banyak savepoint
  • • Release savepoint yang tidak perlu
  • • Dokumentasikan logika savepoint

Praktik TCL

Langkah-langkah Praktik Lengkap

🎯 Tujuan Praktik

Dalam praktik ini, kalian akan belajar menggunakan COMMIT, ROLLBACK, dan SAVEPOINT melalui simulasi sistem manajemen mahasiswa. Setiap langkah akan dipraktikkan secara bertahap.

📋 Langkah 1: Persiapan Database

Pertama, kita akan membuat database baru, kemudian membuat tabel dan data awal untuk praktik.

🎯 Sub Langkah 1A: Membuat Database

Langkah pertama adalah membuat database baru untuk praktik TCL kita.

-- Buat database baru untuk praktik TCL
CREATE DATABASE praktik_tcl;

-- Gunakan database yang baru dibuat
USE praktik_tcl;

-- Cek database yang sedang aktif
SELECT DATABASE() AS database_aktif;

🎯 Sub Langkah 1B: Membuat Tabel

Setelah database siap, kita buat tabel-tabel yang diperlukan.

-- Buat tabel mahasiswa
CREATE TABLE mahasiswa (
    id INT PRIMARY KEY AUTO_INCREMENT,
    nama VARCHAR(50) NOT NULL,
    jurusan VARCHAR(50),
    angkatan INT,
    ipk DECIMAL(3,2)
);

-- Buat tabel nilai
CREATE TABLE nilai (
    id INT PRIMARY KEY AUTO_INCREMENT,
    mahasiswa_id INT,
    mata_kuliah VARCHAR(50),
    nilai INT,
    FOREIGN KEY (mahasiswa_id) REFERENCES mahasiswa(id)
);

-- Cek tabel yang sudah dibuat
SHOW TABLES;

-- Lihat struktur tabel mahasiswa
DESCRIBE mahasiswa;

-- Lihat struktur tabel nilai
DESCRIBE nilai;

🎯 Sub Langkah 1C: Insert Data Awal

Terakhir, kita masukkan data awal untuk keperluan praktik.

-- Insert data awal mahasiswa
INSERT INTO mahasiswa (nama, jurusan, angkatan, ipk) 
VALUES 
('Budi Santoso', 'Teknik Informatika', 2023, 3.50),
('Sari Dewi', 'Sistem Informasi', 2023, 3.75),
('Ahmad Rizki', 'Teknik Komputer', 2022, 3.25);

-- Insert data awal nilai
INSERT INTO nilai (mahasiswa_id, mata_kuliah, nilai) 
VALUES 
(1, 'Pemrograman Web', 85),
(1, 'Database', 90),
(2, 'Sistem Operasi', 88),
(2, 'Jaringan Komputer', 92),
(3, 'Algoritma', 78),
(3, 'Struktur Data', 82);

-- Verifikasi data yang sudah dimasukkan
SELECT * FROM mahasiswa;
SELECT * FROM nilai;

-- Lihat data gabungan
SELECT m.nama, m.jurusan, n.mata_kuliah, n.nilai
FROM mahasiswa m
LEFT JOIN nilai n ON m.id = n.mahasiswa_id
ORDER BY m.nama, n.mata_kuliah;

✅ Tugas: Jalankan semua script di atas secara berurutan untuk membuat database, tabel, dan data awal. Pastikan setiap langkah berhasil sebelum melanjutkan ke langkah berikutnya!

💡 Tips: Jika menggunakan MySQL Workbench atau phpMyAdmin, pastikan kalian sudah terhubung ke server database sebelum menjalankan script ini.

✅ Langkah 2: Praktik COMMIT

Sekarang kita akan mempraktikkan penggunaan COMMIT.

-- Mulai transaksi
START TRANSACTION;

-- Tambah mahasiswa baru
INSERT INTO mahasiswa (nama, jurusan, angkatan, ipk) 
VALUES ('Lisa Permata', 'Teknik Informatika', 2024, 0.00);

-- Cek data yang baru ditambah
SELECT * FROM mahasiswa WHERE nama = 'Lisa Permata';

-- Tambah nilai untuk mahasiswa baru
INSERT INTO nilai (mahasiswa_id, mata_kuliah, nilai) 
VALUES (4, 'Pemrograman Web', 85);

-- Simpan semua perubahan
COMMIT;

-- Verifikasi data tersimpan
SELECT m.nama, m.jurusan, n.mata_kuliah, n.nilai
FROM mahasiswa m
JOIN nilai n ON m.id = n.mahasiswa_id
WHERE m.nama = 'Lisa Permata';

✅ Tugas: Jalankan script di atas dan amati bahwa data tersimpan permanen setelah COMMIT.

↩️ Langkah 3: Praktik ROLLBACK

Mari praktikkan ROLLBACK untuk membatalkan perubahan.

-- Mulai transaksi baru
START TRANSACTION;

-- Cek data sebelum perubahan
SELECT * FROM mahasiswa;

-- Update IPK semua mahasiswa (simulasi kesalahan)
UPDATE mahasiswa 
SET ipk = 4.00;

-- Cek hasil update
SELECT nama, ipk FROM mahasiswa;

-- Ups! Ini salah! Batalkan perubahan
ROLLBACK;

-- Cek data kembali normal
SELECT nama, ipk FROM mahasiswa;

✅ Tugas: Jalankan script dan amati bahwa setelah ROLLBACK, data IPK kembali ke nilai semula.

📍 Langkah 4: Praktik SAVEPOINT

Sekarang praktik SAVEPOINT untuk kontrol yang lebih detail.

START TRANSACTION;

-- Tambah mahasiswa baru
INSERT INTO mahasiswa (nama, jurusan, angkatan, ipk) 
VALUES ('Rina Sari', 'Sistem Informasi', 2024, 0.00);

-- Buat savepoint setelah insert
SAVEPOINT after_insert_mahasiswa;

-- Update jurusan mahasiswa yang baru ditambah
UPDATE mahasiswa 
SET jurusan = 'Teknik Informatika' 
WHERE nama = 'Rina Sari';

-- Buat savepoint setelah update
SAVEPOINT after_update_jurusan;

-- Tambah nilai (simulasi kesalahan)
INSERT INTO nilai (mahasiswa_id, mata_kuliah, nilai) 
VALUES (999, 'Database', 90); -- ID salah!

-- Rollback ke setelah update jurusan
ROLLBACK TO after_update_jurusan;

-- Tambah nilai dengan ID yang benar
INSERT INTO nilai (mahasiswa_id, mata_kuliah, nilai) 
VALUES (
    (SELECT id FROM mahasiswa WHERE nama = 'Rina Sari'), 
    'Database', 90
);

-- Commit semua perubahan
COMMIT;

✅ Tugas: Jalankan script dan amati bagaimana SAVEPOINT memungkinkan rollback parsial.

🏦 Langkah 5: Studi Kasus Kompleks

Praktik kasus kompleks: Update IPK berdasarkan nilai dengan validasi.

START TRANSACTION;

-- Savepoint awal
SAVEPOINT start_update_ipk;

-- Update IPK Budi berdasarkan nilai
UPDATE mahasiswa 
SET ipk = (
    SELECT AVG(nilai)/25.0 
    FROM nilai 
    WHERE mahasiswa_id = mahasiswa.id
) 
WHERE nama = 'Budi Santoso';

SAVEPOINT after_budi_update;

-- Cek hasil update
SELECT nama, ipk FROM mahasiswa WHERE nama = 'Budi Santoso';

-- Jika IPK > 4.0, rollback
SELECT 
    CASE 
        WHEN ipk > 4.0 THEN 'ROLLBACK NEEDED'
        ELSE 'OK'
    END AS status
FROM mahasiswa 
WHERE nama = 'Budi Santoso';

-- Jika perlu, rollback ke savepoint
-- ROLLBACK TO after_budi_update;

-- Atau commit jika valid
COMMIT;

✅ Tugas: Jalankan script dan modifikasi sesuai hasil validasi IPK.
