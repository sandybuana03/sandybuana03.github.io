Pengenalan Database Index

🤓 Apa itu Database Index?

Database Index adalah struktur data khusus yang dibuat untuk mempercepat proses pencarian dan pengambilan data dari tabel database. Bayangkan index seperti daftar isi dalam buku - ia membantu kita menemukan informasi yang kita cari dengan cepat!

📚

Analogi Sederhana

Seperti mencari kata dalam kamus. Tanpa index (urutan alfabetis), kita harus membaca dari halaman pertama. Dengan index, kita langsung ke huruf yang tepat!

⚡

Mengapa Penting?

Dalam database dengan jutaan data, pencarian tanpa index bisa memakan waktu sangat lama. Index membuat pencarian menjadi super cepat!

Konsep Dasar Index

🔍 Bagaimana Index Bekerja?

Index menyimpan salinan data tertentu dari tabel dalam struktur yang terorganisir, biasanya dalam bentuk pohon (B-Tree) atau hash table, sehingga pencarian menjadi lebih efisien.

📊

Struktur Data Index

  • • B-Tree: Struktur pohon seimbang
  • • Hash: Tabel hash untuk pencarian cepat
  • • Bitmap: Untuk data dengan nilai terbatas
⚡

Kompleksitas Waktu

  • • Tanpa Index: O(n) - Linear
  • • Dengan Index: O(log n) - Logaritmik
  • • Hash Index: O(1) - Konstan

📈 Perbandingan Performa

Jumlah Data Tanpa Index Dengan Index Peningkatan
1,000 500 operasi 10 operasi 50x lebih cepat
1,000,000 500,000 operasi 20 operasi 25,000x lebih cepat

💡 Kapan Menggunakan Index?

✅ Gunakan Index Ketika:
  • • Kolom sering digunakan dalam WHERE clause
  • • Kolom untuk JOIN antar tabel
  • • Kolom untuk ORDER BY dan GROUP BY
  • • Tabel dengan banyak data (>10,000 rows)
  • • Query SELECT lebih sering daripada INSERT/UPDATE
  • • Kolom dengan nilai unik atau semi-unik
❌ Hindari Index Ketika:
  • • Tabel kecil (<1,000 rows)
  • • Kolom jarang digunakan dalam query
  • • Tabel sering di-INSERT/UPDATE/DELETE
  • • Kolom dengan nilai yang sering berubah
  • • Storage space sangat terbatas
  • • Kolom dengan banyak nilai NULL
🎯 Rule of Thumb:

Buat index jika kolom tersebut digunakan dalam WHERE clause lebih dari 80% query yang sering dijalankan. Selalu monitor performa sebelum dan sesudah membuat index!

🔍

Jenis-jenis Index

🔑

Primary Index

Index yang dibuat otomatis untuk primary key. Setiap tabel hanya boleh memiliki satu primary index.

CREATE TABLE users (id INT PRIMARY KEY, name VARCHAR(50));
🔗

Unique Index

Index yang memastikan tidak ada nilai duplikat dalam kolom. Cocok untuk email, username, dll.

CREATE UNIQUE INDEX idx_email ON users(email);
📋

Composite Index

Index yang dibuat dari beberapa kolom sekaligus. Berguna untuk query yang menggunakan multiple kolom.

CREATE INDEX idx_name_age ON users(name, age);
🎯

Partial Index

Index yang hanya dibuat untuk sebagian data yang memenuhi kondisi tertentu.

CREATE INDEX idx_active_users ON users(name) WHERE active = true;

🏗️ Berdasarkan Struktur Data

🌳
B-Tree Index

Struktur pohon seimbang yang paling umum digunakan

  • • Keunggulan: Efisien untuk range queries, sorting
  • • Cocok untuk: Kolom dengan data terurut
  • • Kompleksitas: O(log n)
#️⃣
Hash Index

Menggunakan hash function untuk akses langsung

  • • Keunggulan: Sangat cepat untuk equality search
  • • Cocok untuk: WHERE dengan operator = saja
  • • Kompleksitas: O(1)
🗂️
Bitmap Index

Menggunakan bit array untuk data dengan cardinalitas rendah

  • • Keunggulan: Hemat space, cepat untuk AND/OR
  • • Cocok untuk: Gender, status, kategori
  • • Kompleksitas: O(1) untuk operasi bit
📍
Spatial Index

Khusus untuk data geografis dan geometris

  • • Keunggulan: Optimized untuk koordinat
  • • Cocok untuk: GPS, maps, GIS data
  • • Kompleksitas: Tergantung dimensi

⚠️ Tips Memilih Jenis Index

🎯 Panduan Pemilihan Index:
Berdasarkan Tipe Query:
  • • Equality (=): Hash Index atau B-Tree
  • • Range (>, <, BETWEEN): B-Tree Index
  • • Pattern (LIKE): Full-text Index
  • • Multiple columns: Composite Index
Berdasarkan Karakteristik Data:
  • • Unique values: Unique Index
  • • Few distinct values: Bitmap Index
  • • Frequently changing: Hindari index
  • • Large text: Full-text Index
📊 Decision Matrix:
Skenario Jenis Index Alasan
Primary Key Primary Index Otomatis, unik, clustered
Email/Username Unique Index Mencegah duplikasi
Nama + Tanggal Composite Index Query multi-kolom
Status Aktif Partial Index Hanya data aktif
⚡ Pro Tips:
  • • Urutan kolom penting dalam composite index (kolom paling selektif di depan)
  • • Jangan over-indexing - maksimal 5-7 index per tabel
  • • Monitor penggunaan index secara berkala
  • • Test performa sebelum dan sesudah membuat index

🎨 Kapan Menggunakan Jenis Index?

Primary Index:
  • • Otomatis dibuat untuk primary key
  • • Untuk identifikasi unik record
Unique Index:
  • • Email, username, nomor telepon
  • • Data yang harus unik tapi bukan primary key
Composite Index:
  • • Query dengan multiple WHERE conditions
  • • Pencarian berdasarkan kombinasi kolom
Partial Index:
  • • Hanya sebagian data yang sering diakses
  • • Menghemat storage space

Cara Kerja Index

🔄 Proses Internal Index

Mari kita pelajari bagaimana database menggunakan index untuk mempercepat pencarian data step by step!

1

Pembuatan Index

Database membuat struktur data terpisah yang berisi:

  • • Nilai dari kolom yang diindex (sorted)
  • • Pointer ke baris data asli di tabel
  • • Struktur pohon untuk navigasi cepat
2

Query Processing

Ketika ada query dengan WHERE clause:

  • • Database optimizer mengecek apakah ada index yang bisa digunakan
  • • Jika ada, gunakan index untuk pencarian
  • • Jika tidak ada, lakukan full table scan
3

Index Lookup

Proses pencarian menggunakan index:

  • • Mulai dari root node di B-Tree
  • • Navigasi ke leaf node yang tepat
  • • Ambil pointer ke data asli
  • • Retrieve data dari tabel utama

📊 Contoh Praktis: Pencarian Nama

❌ Tanpa Index (Full Table Scan):

Query: SELECT * FROM users WHERE name = 'John';

Proses:

  • 1. Baca baris 1: "Alice" ≠ "John"
  • 2. Baca baris 2: "Bob" ≠ "John"
  • 3. Baca baris 3: "Charlie" ≠ "John"
  • 4. ... terus sampai ketemu "John"
  • 5. Baca semua 1,000,000 baris!
✅ Dengan Index:

Query: SELECT * FROM users WHERE name = 'John';

Proses:

  • 1. Cek index: "John" ada di posisi X
  • 2. Langsung ke baris X di tabel
  • 3. Ambil data "John"
  • 4. Selesai! Hanya 3 operasi
  • 5. 🚀 Super cepat!

📈 Perbandingan Performa

Mari kita lihat perbedaan performa berbagai operasi database dengan dan tanpa index:

Operasi Tanpa Index Dengan Index Keterangan
SELECT WHERE Lambat ⏳ Cepat ⚡ Peningkatan signifikan
INSERT Cepat ⚡ Sedang ⏱️ Sedikit lebih lambat
UPDATE Sedang ⏱️ Sedang ⏱️ Tergantung kolom yang diupdate
DELETE Lambat ⏳ Cepat ⚡ Cepat mencari, lambat menghapus index
🐌 Tanpa Index (Full Table Scan)
1,000 records: ~500 operasi
100,000 records: ~50,000 operasi
1,000,000 records: ~500,000 operasi
10,000,000 records: ~5,000,000 operasi

Kompleksitas: O(n) - Linear
Waktu: Bertambah proporsional dengan jumlah data

⚡ Dengan Index (B-Tree)
1,000 records: ~10 operasi
100,000 records: ~17 operasi
1,000,000 records: ~20 operasi
10,000,000 records: ~24 operasi

Kompleksitas: O(log n) - Logaritmik
Waktu: Bertambah sangat lambat meski data banyak

🚀 Peningkatan Performa SELECT
Jumlah Data Tanpa Index Dengan Index Peningkatan Waktu Estimasi

💡 Insight Penting
  • • SELECT: Index memberikan peningkatan drastis
  • • INSERT: Index menambah overhead sedikit
  • • UPDATE: Bergantung kolom yang dimodifikasi
  • • DELETE: Cepat mencari, tapi harus update index
📊 Real-World Impact
  • • Read-heavy apps: Index sangat menguntungkan
  • • Write-heavy apps: Pertimbangkan trade-off
  • • Mixed workload: Pilih index yang strategis
  • • Monitor performa secara berkala

🎯 Langkah 1: Persiapan Database dan Tabel

Pertama, kita akan membuat database dan tabel untuk praktik:

-- Membuat database
CREATE DATABASE praktik_index;
USE praktik_index;
-- Membuat tabel mahasiswa
CREATE TABLE mahasiswa (

  angkatan YEAR,

🔍 Langkah 3: Testing Query Tanpa Index

Mari kita test performa query sebelum membuat index:

A. Query berdasarkan NIM (belum ada index):

-- Cek performa tanpa index
EXPLAIN SELECT * FROM mahasiswa WHERE nim = '2021001';
SELECT * FROM mahasiswa WHERE nim = '2021001';

B. Query berdasarkan Jurusan (belum ada index):

-- Cek performa tanpa index
EXPLAIN SELECT * FROM mahasiswa WHERE jurusan = 'Teknik Informatika';
SELECT * FROM mahasiswa WHERE jurusan = 'Teknik Informatika';

📊 Perhatikan: Pada hasil EXPLAIN, kolom "type" akan menunjukkan "ALL" yang berarti Full Table Scan. Ini menandakan database harus membaca semua baris untuk menemukan data yang dicari.

🔧 Langkah 4: Membuat Index

Sekarang kita buat berbagai jenis index untuk optimasi:

A. Unique Index untuk NIM:

-- Membuat unique index untuk NIM
CREATE UNIQUE INDEX idx_nim ON mahasiswa(nim);

B. Index untuk Jurusan:

-- Membuat index untuk kolom jurusan
CREATE INDEX idx_jurusan ON mahasiswa(jurusan);

C. Composite Index:

-- Membuat composite index untuk jurusan dan angkatan
CREATE INDEX idx_jurusan_angkatan ON mahasiswa(jurusan, angkatan);

D. Index untuk Email:

-- Membuat index untuk email (sering digunakan untuk login)
CREATE INDEX idx_email ON mahasiswa(email);

⚡ Catatan: Proses pembuatan index mungkin memakan waktu tergantung jumlah data. Untuk tabel besar, sebaiknya buat index saat traffic rendah.

📈 Langkah 5: Testing Query Dengan Index

Sekarang mari kita test performa query setelah membuat index:

A. Query menggunakan NIM (dengan Unique Index):

-- Query ini sekarang menggunakan idx_nim
EXPLAIN SELECT * FROM mahasiswa WHERE nim = '2021001';
SELECT * FROM mahasiswa WHERE nim = '2021001';

B. Query menggunakan Jurusan (dengan Single Index):

-- Query ini sekarang menggunakan idx_jurusan
EXPLAIN SELECT * FROM mahasiswa WHERE jurusan = 'Teknik Informatika';
SELECT * FROM mahasiswa WHERE jurusan = 'Teknik Informatika';

C. Query menggunakan Composite Index:

-- Query ini menggunakan idx_jurusan_angkatan
EXPLAIN SELECT * FROM mahasiswa WHERE jurusan = 'Teknik Informatika' AND angkatan = 2021;
SELECT * FROM mahasiswa WHERE jurusan = 'Teknik Informatika' AND angkatan = 2021;

🚀 Bandingkan: Sekarang pada hasil EXPLAIN, kolom "type" akan menunjukkan "ref" atau "const" dan kolom "key" akan menampilkan nama index yang digunakan. Ini menandakan query sudah optimal!

🔍 Langkah 6: Melihat Index yang Ada

Mari kita lihat semua index yang telah dibuat:

A. Melihat Semua Index pada Tabel:

-- Lihat semua index yang ada di tabel mahasiswa
SHOW INDEX FROM mahasiswa;

B. Melihat Informasi Detail Index:

-- Informasi detail tentang index
SELECT * FROM information_schema.STATISTICS
WHERE table_schema = 'praktik_index'
AND table_name = 'mahasiswa';

C. Melihat Ukuran Index:

-- Cek ukuran tabel dan index
SELECT table_name, data_length, index_length,
       ROUND((data_length + index_length) / 1024 / 1024, 2) AS 'Total Size (MB)'
FROM information_schema.TABLES
WHERE table_schema = 'praktik_index';

📊 Interpretasi: Perhatikan kolom "Cardinality" yang menunjukkan estimasi jumlah nilai unik. Semakin tinggi cardinality, semakin efektif index tersebut.

🗑️ Langkah 7: Menghapus Index

Pelajari cara menghapus index yang tidak diperlukan:

A. Menghapus Index Tunggal:

-- Hapus index yang jarang digunakan
DROP INDEX idx_email ON mahasiswa;

B. Menghapus Multiple Index:

-- Hapus beberapa index sekaligus
ALTER TABLE mahasiswa
DROP INDEX idx_jurusan,
DROP INDEX idx_jurusan_angkatan;

C. Verifikasi Penghapusan:

-- Pastikan index sudah terhapus
SHOW INDEX FROM mahasiswa;

⚠️ Peringatan: Selalu backup database sebelum menghapus index. Pastikan index yang dihapus benar-benar tidak diperlukan untuk menghindari penurunan performa query.
