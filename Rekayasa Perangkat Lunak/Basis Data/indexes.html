Pengenalan Database Index

🤓 Apa itu Database Index?

Database Index adalah struktur data khusus yang dibuat untuk mempercepat proses pencarian dan pengambilan data dari tabel database. Bayangkan index seperti daftar isi dalam buku - ia membantu kita menemukan informasi yang kita cari dengan cepat!

📚

Analogi Sederhana

Seperti mencari kata dalam kamus. Tanpa index (urutan alfabetis), kita harus membaca dari halaman pertama. Dengan index, kita langsung ke huruf yang tepat!

⚡

Mengapa Penting?

Dalam database dengan jutaan data, pencarian tanpa index bisa memakan waktu sangat lama. Index membuat pencarian menjadi super cepat!

Konsep Dasar Index

🔍 Bagaimana Index Bekerja?

Index menyimpan salinan data tertentu dari tabel dalam struktur yang terorganisir, biasanya dalam bentuk pohon (B-Tree) atau hash table, sehingga pencarian menjadi lebih efisien.

📊

Struktur Data Index

  • • B-Tree: Struktur pohon seimbang
  • • Hash: Tabel hash untuk pencarian cepat
  • • Bitmap: Untuk data dengan nilai terbatas
⚡

Kompleksitas Waktu

  • • Tanpa Index: O(n) - Linear
  • • Dengan Index: O(log n) - Logaritmik
  • • Hash Index: O(1) - Konstan

📈 Perbandingan Performa

Jumlah Data Tanpa Index Dengan Index Peningkatan
1,000 500 operasi 10 operasi 50x lebih cepat
1,000,000 500,000 operasi 20 operasi 25,000x lebih cepat
🔍

Jenis-jenis Index

🔑

Primary Index

Index yang dibuat otomatis untuk primary key. Setiap tabel hanya boleh memiliki satu primary index.

CREATE TABLE users (id INT PRIMARY KEY, name VARCHAR(50));
🔗

Unique Index

Index yang memastikan tidak ada nilai duplikat dalam kolom. Cocok untuk email, username, dll.

CREATE UNIQUE INDEX idx_email ON users(email);
📋

Composite Index

Index yang dibuat dari beberapa kolom sekaligus. Berguna untuk query yang menggunakan multiple kolom.

CREATE INDEX idx_name_age ON users(name, age);
🎯

Partial Index

Index yang hanya dibuat untuk sebagian data yang memenuhi kondisi tertentu.

CREATE INDEX idx_active_users ON users(name) WHERE active = true;

🎨 Kapan Menggunakan Jenis Index?

Primary Index:
  • • Otomatis dibuat untuk primary key
  • • Untuk identifikasi unik record
Unique Index:
  • • Email, username, nomor telepon
  • • Data yang harus unik tapi bukan primary key
Composite Index:
  • • Query dengan multiple WHERE conditions
  • • Pencarian berdasarkan kombinasi kolom
Partial Index:
  • • Hanya sebagian data yang sering diakses
  • • Menghemat storage space

Cara Kerja Index

🔄 Proses Internal Index

Mari kita pelajari bagaimana database menggunakan index untuk mempercepat pencarian data step by step!

1

Pembuatan Index

Database membuat struktur data terpisah yang berisi:

  • • Nilai dari kolom yang diindex (sorted)
  • • Pointer ke baris data asli di tabel
  • • Struktur pohon untuk navigasi cepat
2

Query Processing

Ketika ada query dengan WHERE clause:

  • • Database optimizer mengecek apakah ada index yang bisa digunakan
  • • Jika ada, gunakan index untuk pencarian
  • • Jika tidak ada, lakukan full table scan
3

Index Lookup

Proses pencarian menggunakan index:

  • • Mulai dari root node di B-Tree
  • • Navigasi ke leaf node yang tepat
  • • Ambil pointer ke data asli
  • • Retrieve data dari tabel utama

📊 Contoh Praktis: Pencarian Nama

❌ Tanpa Index (Full Table Scan):

Query: SELECT * FROM users WHERE name = 'John';

Proses:

  • 1. Baca baris 1: "Alice" ≠ "John"
  • 2. Baca baris 2: "Bob" ≠ "John"
  • 3. Baca baris 3: "Charlie" ≠ "John"
  • 4. ... terus sampai ketemu "John"
  • 5. Baca semua 1,000,000 baris!
✅ Dengan Index:

Query: SELECT * FROM users WHERE name = 'John';

Proses:

  • 1. Cek index: "John" ada di posisi X
  • 2. Langsung ke baris X di tabel
  • 3. Ambil data "John"
  • 4. Selesai! Hanya 3 operasi
  • 5. 🚀 Super cepat!

Keuntungan & Kerugian Index

✅

Keuntungan Index

🚀

Performa Query Lebih Cepat

Pencarian data menjadi sangat cepat, terutama pada tabel besar

🔍

Efisiensi JOIN

Operasi JOIN antar tabel menjadi lebih efisien

📊

Sorting Lebih Cepat

ORDER BY menggunakan index yang sudah terurut

🎯

Unique Constraint

Memastikan data unik dengan cepat

❌

Kerugian Index

💾

Membutuhkan Storage Tambahan

Index memakan ruang disk yang cukup besar

⏳

INSERT/UPDATE/DELETE Lebih Lambat

Index harus diupdate setiap ada perubahan data

🔧

Maintenance Overhead

Perlu maintenance berkala untuk performa optimal

🤔

Kompleksitas Planning

Perlu perencanaan yang baik untuk index yang tepat

💡 Best Practices: Kapan Menggunakan Index?

✅ Gunakan Index Ketika:
  • • Kolom sering digunakan dalam WHERE clause
  • • Kolom untuk JOIN antar tabel
  • • Kolom untuk ORDER BY
  • • Tabel memiliki banyak data (>1000 rows)
  • • Query SELECT lebih sering daripada INSERT/UPDATE
❌ Hindari Index Ketika:
  • • Tabel kecil (<1000 rows)
  • • Kolom jarang digunakan dalam query
  • • Tabel sering di-INSERT/UPDATE/DELETE
  • • Kolom dengan nilai yang sering berubah
  • • Storage space terbatas

🎯 Langkah 1: Persiapan Database dan Tabel

Pertama, kita akan membuat database dan tabel untuk praktik:

-- Membuat database
CREATE DATABASE praktik_index;
USE praktik_index;
-- Membuat tabel mahasiswa
CREATE TABLE mahasiswa (
  id INT AUTO_INCREMENT PRIMARY KEY,
  nim VARCHAR(10) NOT NULL,
  nama VARCHAR(100) NOT NULL,
  email VARCHAR(100) NOT NULL,
  jurusan VARCHAR(50),
  angkatan YEAR,
  ipk DECIMAL(3,2)
);

🔧 Langkah 2: Membuat Index

Sekarang kita buat berbagai jenis index:

A. Unique Index untuk NIM:

CREATE UNIQUE INDEX idx_nim ON mahasiswa(nim);

B. Index untuk Jurusan:

CREATE INDEX idx_jurusan ON mahasiswa(jurusan);

C. Composite Index:

CREATE INDEX idx_jurusan_angkatan ON mahasiswa(jurusan, angkatan);

📊 Langkah 3: Insert Sample Data

Mari kita masukkan beberapa data untuk testing:

INSERT INTO mahasiswa (nim, nama, email, jurusan, angkatan, ipk) VALUES

('2021002', 'Siti Nurhaliza', 'siti@email.com', 'Sistem Informasi', 2021, 3.85),
('2022001', 'Budi Santoso', 'budi@email.com', 'Teknik Informatika', 2022, 3.60),
('2022002', 'Dewi Lestari', 'dewi@email.com', 'Multimedia', 2022, 3.90),
('2023001', 'Eko Prasetyo', 'eko@email.com', 'Teknik Informatika', 2023, 3.70);

🔍 Langkah 4: Testing Query dengan Index

Sekarang mari kita test performa query:

A. Query menggunakan NIM (Unique Index):

-- Query ini akan menggunakan idx_nim
SELECT * FROM mahasiswa WHERE nim = '2021001';

B. Query menggunakan Jurusan (Single Index):

-- Query ini akan menggunakan idx_jurusan
SELECT * FROM mahasiswa WHERE jurusan = 'Teknik Informatika';

C. Query menggunakan Composite Index:

-- Query ini akan menggunakan idx_jurusan_angkatan
SELECT * FROM mahasiswa WHERE jurusan = 'Teknik Informatika' AND angkatan = 2021;

📈 Langkah 5: Mengecek Penggunaan Index

Untuk memastikan query menggunakan index, gunakan EXPLAIN:

-- Cek apakah query menggunakan index
EXPLAIN SELECT * FROM mahasiswa WHERE nim = '2021001';
-- Lihat semua index yang ada di tabel
SHOW INDEX FROM mahasiswa;

💡 Tips: Pada kolom "Key" di hasil EXPLAIN, jika tertulis nama index (bukan NULL), berarti query tersebut menggunakan index dan akan berjalan lebih cepat!

🔧 Langkah 6: Mengelola Index

Pelajari cara mengelola index untuk performa optimal:

A. Menghapus Index yang Tidak Diperlukan:

-- Hapus index yang jarang digunakan
DROP INDEX idx_jurusan ON mahasiswa;

B. Mengubah Nama Index:

-- Rename index untuk penamaan yang lebih baik
ALTER TABLE mahasiswa RENAME INDEX idx_nim TO idx_mahasiswa_nim;

C. Monitoring Penggunaan Index:

-- Cek statistik penggunaan index (MySQL 5.6+)
SELECT * FROM information_schema.STATISTICS
WHERE table_name = 'mahasiswa';

D. Optimasi Index:

-- Rebuild index untuk optimasi
ALTER TABLE mahasiswa ENGINE=InnoDB;
-- Analyze table untuk update statistik
ANALYZE TABLE mahasiswa;

⚠️ Peringatan: Selalu backup database sebelum menghapus atau mengubah index. Monitor performa setelah perubahan untuk memastikan tidak ada degradasi performance.
