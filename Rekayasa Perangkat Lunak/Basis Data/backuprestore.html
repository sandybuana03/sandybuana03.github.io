📖 Pengenalan Backup & Restore MySQL

🗄️ Apa itu Backup Database?

Backup database adalah proses membuat salinan cadangan dari seluruh data, struktur tabel, dan konfigurasi database. Bayangkan seperti mem-fotocopy semua dokumen penting dan menyimpannya di tempat yang aman!

🎯 Mengapa Backup Penting?

🛡️

Perlindungan Data

Melindungi dari kehilangan data akibat kerusakan hardware

🔄

Recovery Cepat

Memulihkan data dengan cepat saat terjadi masalah

👥

Human Error

Mengatasi kesalahan penghapusan data oleh user

🦠

Serangan Malware

Melindungi dari virus dan ransomware

🔄 Apa itu Restore Database?

Restore adalah proses mengembalikan database dari file backup ke kondisi semula. Seperti mengembalikan foto yang terhapus dari recycle bin atau cloud storage!

⚡ Kapan Perlu Restore?

💥

Server Crash

Ketika server database mengalami kerusakan

🗑️

Data Terhapus

Saat data penting terhapus secara tidak sengaja

🔄

Migrasi Server

Memindahkan database ke server baru

🧠 Konsep Dasar Backup MySQL

📊 Komponen yang Di-backup

📋

Data

Semua record dalam tabel database

🏗️

Struktur

Skema tabel, index, dan relasi

⚙️

Konfigurasi

User, permission, dan setting

📈 Strategi Backup

🔴Full Backup

Backup lengkap seluruh database

✅ Kelebihan:

  • • Restore mudah dan cepat
  • • Data lengkap tersimpan

❌ Kekurangan:

  • • Membutuhkan storage besar
  • • Proses backup lama

🟡Incremental Backup

Backup hanya perubahan sejak backup terakhir

✅ Kelebihan:

  • • Hemat storage
  • • Proses cepat

❌ Kekurangan:

  • • Restore lebih kompleks
  • • Butuh backup sebelumnya

📋 Jenis-Jenis Backup MySQL

🔄 Berdasarkan Metode

🔵Logical Backup

Backup dalam bentuk SQL statements

📄 Format: SQL Script

File .sql berisi perintah CREATE, INSERT

🛠️ Tool: mysqldump

Tool bawaan MySQL untuk logical backup

📖 Readable: Ya

Bisa dibaca dan diedit manual

🟢Physical Backup

Backup file database secara langsung

📁 Format: Binary Files

Copy langsung file .frm, .ibd, .MYD

⚡ Speed: Sangat Cepat

Tidak perlu export/import data

🔒 Readable: Tidak

File binary, tidak bisa dibaca manual

⏰ Berdasarkan Waktu

🔴

Hot Backup

Backup saat database aktif

✅ Tidak mengganggu user

✅ Database tetap online

❌ Butuh tools khusus

🟡

Warm Backup

Backup dengan akses terbatas

✅ Konsistensi data baik

⚠️ Read-only mode

❌ Tidak bisa write

🔵

Cold Backup

Backup saat database offline

✅ Konsistensi sempurna

✅ Proses mudah

❌ Database offline

🛠️ Tools untuk Backup MySQL

⚡ mysqldump - Tool Utama

mysqldump adalah tool bawaan MySQL yang paling populer untuk membuat logical backup. Tool ini menghasilkan file SQL yang berisi semua perintah untuk merecreate database.

📦 Gratis & Built-in

Sudah termasuk dalam instalasi MySQL

🔄 Cross-platform

Bisa restore ke MySQL versi berbeda

📖 Human Readable

File SQL bisa dibaca dan diedit

🐌 Lambat untuk DB Besar

🔒 Lock Tables

⚡ Praktik Backup & Restore MySQL

Mari praktik langsung step by step!

🎯 Langkah 1: Persiapan

📋 Yang Perlu Disiapkan:

💻 MySQL Server terinstall
🗄️ Database sample untuk latihan
⌨️ Command Line / Terminal
📁 Folder untuk menyimpan backup

🚀 Membuat Database Sample:

# Login ke MySQL

mysql -u root -p


# Buat database baru

CREATE DATABASE sekolah_smk;

USE sekolah_smk;


# Buat tabel siswa

CREATE TABLE siswa (

  id INT PRIMARY KEY AUTO_INCREMENT,

  nama VARCHAR(100),

  kelas VARCHAR(10),

  jurusan VARCHAR(50)

);


# Insert data sample

INSERT INTO siswa VALUES

(1, 'Andi Pratama', 'XII', 'RPL'),

(2, 'Sari Dewi', 'XI', 'TKJ'),

(3, 'Budi Santoso', 'X', 'MM');

💾 Langkah 2: Backup dengan mysqldump

📤 Backup Satu Database:

# Syntax dasar

mysqldump -u [username] -p [database_name] > backup_file.sql


# Contoh praktik

mysqldump -u root -p sekolah_smk > backup_sekolah.sql

Penjelasan:

  • • -u root : Login sebagai user root
  • • -p : Akan meminta password
  • • sekolah_smk : Nama database yang akan di-backup
  • • > backup_sekolah.sql : Output ke file SQL

🗄️ Backup Semua Database:

# Backup semua database

mysqldump -u root -p --all-databases > backup_all.sql


# Backup beberapa database spesifik

mysqldump -u root -p --databases sekolah_smk perpustakaan > backup_multi.sql

⚙️ Opsi Backup Lanjutan:

# Backup dengan kompresi

mysqldump -u root -p sekolah_smk | gzip > backup_sekolah.sql.gz


# Backup hanya struktur (tanpa data)

mysqldump -u root -p --no-data sekolah_smk > struktur_only.sql


# Backup hanya data (tanpa struktur)

mysqldump -u root -p --no-create-info sekolah_smk > data_only.sql


# Backup dengan timestamp

mysqldump -u root -p sekolah_smk > backup_$(date +%Y%m%d_%H%M%S).sql

🔄 Langkah 3: Restore Database

📥 Restore ke Database Baru:

# 1. Buat database baru dulu

mysql -u root -p

CREATE DATABASE sekolah_restore;

EXIT;


# 2. Restore dari file backup

mysql -u root -p sekolah_restore < backup_sekolah.sql

⚠️ Penting: Database tujuan harus sudah dibuat terlebih dahulu!

🔄 Restore Menimpa Database Existing:

# Restore langsung ke database yang ada

mysql -u root -p sekolah_smk < backup_sekolah.sql


# Restore dari file terkompresi

gunzip < backup_sekolah.sql.gz | mysql -u root -p sekolah_smk

⚠️ Hati-hati: Ini akan menimpa data yang ada!

✅ Verifikasi Hasil Restore:

# Login dan cek database

mysql -u root -p

USE sekolah_restore;

SHOW TABLES;

SELECT * FROM siswa;

DESCRIBE siswa;

🚀 Langkah 4: Praktik Lanjutan

🤖 Otomasi Backup dengan Script:

#!/bin/bash

# Script backup otomatis


DATE=$(date +%Y%m%d_%H%M%S)

BACKUP_DIR="/backup/mysql"

DATABASE="sekolah_smk"

USER="root"

PASSWORD="your_password"


# Buat direktori jika belum ada

mkdir -p $BACKUP_DIR


# Backup database

mysqldump -u$USER -p$PASSWORD $DATABASE | gzip > $BACKUP_DIR/backup_$DATE.sql.gz


# Hapus backup lama (lebih dari 7 hari)

find $BACKUP_DIR -name "backup_*.sql.gz" -mtime +7 -delete


echo "Backup selesai: backup_$DATE.sql.gz"

⏰ Penjadwalan Backup dengan Cron:

# Edit crontab

crontab -e


# Backup setiap hari jam 2 pagi

0 2 * * * /path/to/backup_script.sh


# Backup setiap 6 jam

0 */6 * * * /path/to/backup_script.sh


# Backup setiap Minggu jam 1 pagi

0 1 * * 0 /path/to/backup_script.sh

🔍 Tips Troubleshooting:

❌ Error: Access denied

Solusi: Periksa username, password, dan privileges user

GRANT ALL PRIVILEGES ON *.* TO 'user'@'localhost';

❌ Error: Table doesn't exist

Solusi: Pastikan database tujuan kosong atau gunakan --add-drop-table

mysqldump --add-drop-table -u root -p database > backup.sql

❌ File backup terlalu besar

Solusi: Gunakan kompresi atau backup per tabel

mysqldump -u root -p database table_name > backup_table.sql
