Pengenalan Dokumen Teknis

Mari kenali apa itu dokumen teknis dan mengapa penting

📖 Apa itu Dokumen Teknis?

Dokumen teknis adalah panduan tertulis yang menjelaskan cara kerja, penggunaan, atau spesifikasi dari suatu sistem, aplikasi, atau teknologi. Seperti buku manual yang membantu orang memahami sesuatu yang kompleks dengan bahasa yang mudah dipahami.

💡 Analogi sederhana:

Dokumen teknis seperti resep masakan - memberikan langkah-langkah jelas agar orang lain bisa mengikuti dan mendapatkan hasil yang sama!

🌍 Dokumen Teknis di Dunia Nyata

📱 Contoh Sehari-hari

  • • Manual HP/gadget yang kalian beli
  • • Panduan instalasi aplikasi
  • • Tutorial YouTube cara setting WiFi
  • • Instruksi merakit furniture IKEA
  • • Help center di website/aplikasi

💼 Di Dunia Kerja IT

  • • Dokumentasi sistem perusahaan
  • • Panduan untuk developer baru
  • • Manual troubleshooting IT
  • • Spesifikasi project untuk client
  • • Dokumentasi database dan server

Spesifikasi Kebutuhan

Belajar membuat dokumen spesifikasi yang jelas dan lengkap

🎯 Apa itu Spesifikasi Kebutuhan?

Spesifikasi kebutuhan adalah dokumen yang menjelaskan secara detail apa yang harus dilakukan oleh suatu sistem atau aplikasi. Seperti daftar belanja yang sangat detail - kita tulis semua yang dibutuhkan agar tidak ada yang terlewat!

🏗️ Contoh Analogi:

Seperti blueprint rumah sebelum dibangun - arsitek harus tahu berapa kamar, di mana dapur, berapa luas, dll. Spesifikasi kebutuhan adalah "blueprint" untuk software!

📝 Komponen Utama Spesifikasi Kebutuhan

1️⃣ Kebutuhan Fungsional

Apa yang harus bisa dilakukan sistem

Contoh: "Sistem harus bisa login user"

2️⃣ Kebutuhan Non-Fungsional

Kualitas yang harus dipenuhi sistem

Contoh: "Sistem harus cepat (< 3 detik)"

3️⃣ Batasan Sistem

Apa yang TIDAK bisa dilakukan sistem

Contoh: "Sistem tidak support IE"

4️⃣ Asumsi & Ketergantungan

Hal yang diasumsikan tersedia

Contoh: "User punya koneksi internet"

🤖 Apa itu API?

API (Application Programming Interface) adalah cara aplikasi berkomunikasi satu sama lain. Bayangkan API seperti pelayan di restoran - kamu pesan makanan (request), pelayan sampaikan ke dapur, lalu bawa makanan kembali (response).

🍽️ Analogi Restoran:

👤

Kamu (Client)

Memesan makanan

🍽️

Pelayan (API)

Menyampaikan pesanan

👨‍🍳

Dapur (Server)

Memproses & memberi makanan

🌐 HTTP Methods (Metode HTTP)

GET

Mengambil Data

Seperti membaca buku

POST

Menambah Data

Seperti menulis catatan baru

PUT

Mengubah Data

Seperti mengedit tulisan

DELETE

Menghapus Data

Seperti membuang kertas

                                Studi Kasus: Aplikasi E-Learning SMK
                            

                            

                                
📖 Contoh Spesifikasi Kebutuhan Lengkap

                                

                                    

                                        
1. PENDAHULUAN

                                        

                                            
Tujuan: Membuat aplikasi e-learning untuk SMK Teknologi

                                            
Ruang Lingkup: Sistem pembelajaran online untuk siswa dan guru

                                            
Target User: Siswa, Guru, Admin Sekolah

                                        

                                    

                                    
                                    

                                        
2. KEBUTUHAN FUNGSIONAL

                                        

                                            
• Siswa dapat login dengan NIS

                                            
• Siswa dapat mengakses materi pembelajaran

                                            
• Siswa dapat mengerjakan quiz dan tugas

                                            
• Guru dapat upload materi dan membuat quiz

                                            
• Admin dapat mengelola data siswa dan guru

                                        

                                    

                                    
                                    

                                        
3. KEBUTUHAN NON-FUNGSIONAL

                                        

                                            
• Response time < 3 detik

                                            
• Dapat diakses 500 user bersamaan

                                            
• Interface responsive (mobile-friendly)

                                            
• Data tersimpan aman dengan enkripsi

                                📝
                                Tugas: Membuat Spesifikasi Kebutuhan
                            

                            

                                
🎯 Skenario:

                                

                                    Sekolah kalian ingin membuat aplikasi perpustakaan digital sederhana. Siswa bisa mencari buku, meminjam buku, dan melihat riwayat peminjaman.
                                

                                
                                
📋 Yang harus kalian buat:

                                

                                    

                                        
1. Kebutuhan Fungsional

                                        
Tuliskan minimal 5 kebutuhan fungsional, contoh:

                                        
    
                                            
  • • Siswa dapat mencari buku berdasarkan judul
    • 
                                            
  • • Siswa dapat meminjam buku
    • 
                                            
  • • [Lanjutkan dengan kebutuhan lainnya...]
    • 
                                        

                                    

                                    
                                    

                                        
2. Kebutuhan Non-Fungsional

                                        
Tuliskan minimal 3 kebutuhan non-fungsional, seperti:

                                        
    
                                            
  • • Kecepatan response
    • 
                                            
  • • Keamanan data
    • 
                                            
  • • [Tambahkan lainnya...]
    •
