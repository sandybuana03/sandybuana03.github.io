Pengenalan Versioning dan Deployment

🏠 Analogi: Membangun dan Mengelola Rumah

🏗️

Versioning = Dokumentasi Renovasi

Seperti mencatat setiap perubahan rumah: kapan cat ulang, kapan ganti genteng, kapan tambah kamar.

📅 Jan 2024: Rumah selesai dibangun
📅 Mar 2024: Tambah teras depan
📅 Jun 2024: Renovasi kamar mandi
🌍

Deployment = Buka Rumah untuk Umum

Seperti membuka rumah sebagai homestay agar orang lain bisa menginap dan menikmatinya.

🏠 Rumah pribadi → Siap untuk tamu
📍 Alamat jelas → URL website
🔑 Akses 24/7 → Server online
📝

Apa itu Versioning?

Versioning adalah cara untuk melacak dan mengelola perubahan pada kode program. Seperti menyimpan berbagai versi dokumen, tapi untuk kode!

Contoh Evolusi Website Toko Online:

Jan 2024
v1.1 + Fitur keranjang belanja
Feb 2024
v1.2 + Sistem pembayaran
Mar 2024
v2.0 Redesign total + mobile app
Jun 2024

Git dan GitHub

🌳 Apa itu Git?

Git adalah software untuk version control. Bayangkan seperti mesin waktu untuk kode kalian! Bisa melihat perubahan, kembali ke versi lama, dan menggabungkan pekerjaan tim.

Perintah Git Dasar:

git init Mulai proyek Git baru
git add . Siapkan semua file untuk disimpan
git commit -m "pesan" Simpan perubahan dengan pesan
git push Upload ke GitHub

🐙 Apa itu GitHub?

GitHub adalah platform online untuk menyimpan kode Git. Seperti Google Drive tapi khusus untuk programmer! Di sini kalian bisa berbagi kode, berkolaborasi, dan showcase portfolio.

📁 Fitur Repository

  • • Simpan kode secara online
  • • Akses dari mana saja
  • • Backup otomatis
  • • Riwayat lengkap perubahan

👥 Fitur Kolaborasi

  • • Kerja tim dalam satu proyek
  • • Pull request untuk review kode
  • • Issue tracking untuk bug
  • • Wiki untuk dokumentasi

🌳 Git Branching: Kerja Tim yang Efektif

Branching memungkinkan beberapa developer bekerja pada fitur berbeda tanpa saling mengganggu.

🎯 Skenario Tim Development

main: Kode production yang stabil
feature/login: Andi buat fitur login
feature/payment: Budi buat sistem bayar
bugfix/cart: Citra perbaiki bug keranjang

⚡ Perintah Branching

git branch feature/login
Buat branch baru
git checkout feature/login
Pindah ke branch
git merge feature/login
Gabungkan ke main
git branch -d feature/login
Hapus branch setelah merge

⚔️ Mengatasi Merge Conflict

Conflict terjadi ketika dua developer mengubah baris kode yang sama. Ini normal dan bisa diatasi!

🔥 Contoh Conflict:

<<<<<<< HEAD
<title>Toko Online Keren</title>
=======
<title>Marketplace Terbaik</title>
>>>>>>> feature/new-title
1. Identifikasi Conflict
Git akan menandai file yang conflict
2. Edit Manual
Pilih versi yang benar atau gabungkan
3. Commit Hasil
Simpan hasil penyelesaian conflict

🎯 Demo: Workflow Git Lengkap

1
git init & Buat file index.html
Inisialisasi repository dan buat file pertama
2
git add . && git commit -m "Initial commit"
Staging dan commit pertama
3
git branch feature/navbar
Buat branch untuk fitur navbar
4
Develop navbar & commit changes
Kerjakan fitur di branch terpisah
5
git checkout main && git merge feature/navbar
Kembali ke main dan merge fitur
6
git push origin main
Upload ke GitHub repository

🚀 GitHub: Lebih dari Sekedar Storage

🔄

Pull Request (PR)

Cara untuk mengusulkan perubahan kode dan meminta review dari tim.

1. Push branch ke GitHub
2. Buat Pull Request
3. Tim review kode
4. Merge setelah approved
🐛

Issues & Bug Tracking

Sistem untuk melacak bug, feature request, dan diskusi proyek.

• Buat issue untuk bug/feature
• Assign ke developer
• Label & milestone
• Close otomatis via commit
📊

GitHub Actions

Otomatisasi testing, building, dan deployment langsung dari GitHub.

• Auto-test setiap push
• Deploy ke production
• Send notifications
• Custom workflows
🌟

GitHub Pages

Hosting gratis untuk website statis langsung dari repository.

• Gratis untuk public repo
• Custom domain support
• Auto-deploy dari branch
• HTTPS by default

Deployment - Publikasi Aplikasi

🚀 Apa itu Deployment?

Deployment adalah proses memindahkan aplikasi dari komputer developer ke server agar bisa diakses melalui internet. Seperti membuka toko fisik setelah menyiapkan semua barang dagangan!

💻
Development
Kode di komputer
📤
Upload
Kirim ke server
🌍
Live
Bisa diakses online

🏠 Platform Hosting Gratis

GH
GitHub Pages
Gratis untuk website statis
  • ✅ Gratis selamanya
  • ✅ Mudah setup
  • ✅ Custom domain
  • ❌ Hanya website statis
N
Netlify
Platform modern untuk web
  • ✅ Deploy otomatis dari Git
  • ✅ Form handling
  • ✅ CDN global
  • ⚠️ Limit bandwidth gratis
▲
Vercel
Platform untuk frontend
  • ✅ Deploy super cepat
  • ✅ Preview untuk setiap commit
  • ✅ Optimasi otomatis
  • ⚠️ Limit usage gratis
F
Firebase
Platform Google
  • ✅ Hosting + Database
  • ✅ SSL otomatis
  • ✅ Analytics built-in
  • ⚠️ Perlu akun Google

📋 Langkah-langkah Deployment

1
Persiapan Kode
Pastikan kode sudah siap dan tidak ada error. Test di local terlebih dahulu.
2
Upload ke Repository
Push kode ke GitHub atau platform Git lainnya.
3
Pilih Platform Hosting
Daftar di platform hosting seperti Netlify, Vercel, atau GitHub Pages.
4
Konfigurasi Deployment
Hubungkan repository dengan platform hosting dan atur konfigurasi.
5
Deploy & Test
Deploy aplikasi dan test apakah berjalan dengan baik di production.

CI/CD - Otomatisasi Deployment

🔄 Apa itu CI/CD?

🔧

Continuous Integration (CI)

Proses otomatis untuk menggabungkan kode dari berbagai developer dan menjalankan test.

  • • Otomatis test kode baru
  • • Deteksi error lebih cepat
  • • Integrasi kode yang aman
🚀

Continuous Deployment (CD)

Proses otomatis untuk deploy aplikasi ke production setelah semua test berhasil.

  • • Deploy otomatis ke server
  • • Rilis lebih cepat dan sering
  • • Rollback otomatis jika error

🏭 Pipeline CI/CD

Pipeline adalah serangkaian langkah otomatis yang dijalankan setiap kali ada perubahan kode:

📝
Code Push
Developer push kode
→
🔍
Test
Jalankan automated test
→
📦
Build
Compile dan package
→
🚀
Deploy
Upload ke production
