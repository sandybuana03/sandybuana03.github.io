✨ Solusi: Version Control System

Version Control adalah sistem yang mencatat setiap perubahan pada file kode program. Bayangkan seperti "mesin waktu" untuk kode kamu!

🎯 Manfaat Version Control:

  • ✅ Menyimpan riwayat semua perubahan kode
  • ✅ Bisa kembali ke versi sebelumnya kapan saja
  • ✅ Bekerja sama dengan tim tanpa konflik
  • ✅ Backup otomatis di cloud
  • ✅ Melacak siapa yang mengubah apa dan kapan
🔧

Apa itu Git?

🎯 Definisi Git

Git adalah software Version Control System yang paling populer di dunia. Dibuat oleh Linus Torvalds (pembuat Linux) pada tahun 2005. Git adalah sistem terdistribusi yang memungkinkan setiap developer memiliki salinan lengkap dari riwayat project.

🌟 Keunggulan Git:

✅ Gratis dan Open Source
✅ Sangat Cepat dan Efisien
✅ Bekerja Offline (Distributed)
✅ Branching & Merging Mudah
✅ Integritas Data Terjamin
✅ Mendukung Kolaborasi Tim

📊 Konsep Dasar Git

📁

Repository (Repo)

Folder project yang dikelola oleh Git. Berisi semua file, riwayat perubahan, dan metadata Git dalam folder .git

📸

Commit

Snapshot/foto dari kondisi project pada waktu tertentu. Setiap commit memiliki ID unik (hash) dan pesan deskriptif.

🌿

Branch

Cabang pengembangan terpisah. Memungkinkan eksperimen fitur baru tanpa merusak kode utama (main/master branch).

🔄

Merge

Proses menggabungkan perubahan dari satu branch ke branch lain. Git otomatis menggabungkan jika tidak ada konflik.

🏷️

Tag

Penanda untuk commit tertentu, biasanya digunakan untuk menandai versi release (v1.0, v2.0, dll).

🎮 Simulasi: Workflow Git Sederhana

Step 1: git init - Inisialisasi repository Git baru di folder project
Step 2: git add . - Menambahkan semua file ke staging area
Step 3: git commit -m "Initial commit" - Menyimpan snapshot pertama
Step 4: git remote add origin [URL] - Menghubungkan ke repository GitHub
Step 5: git push -u origin main - Upload dan set upstream branch
✅ Selesai: Project berhasil di-upload ke GitHub!

GitHub Basics

🌐 Apa itu GitHub?

GitHub adalah platform cloud untuk menyimpan repository Git. Seperti "Google Drive" khusus untuk kode program!

🏢 GitHub vs Git

  • Git: Software di komputer
  • GitHub: Website di internet
  • Git: Lokal/offline
  • GitHub: Cloud/online

🎯 Fungsi GitHub

  • • Backup kode di cloud
  • • Kolaborasi dengan tim
  • • Showcase portfolio
  • • Open source projects

Integrasi Git dengan Android Studio

🔧 Setup Git di Android Studio

📥 Install Git

Download dan install Git dari git-scm.com

Windows: Download Git for Windows
Mac: brew install git
Linux: sudo apt install git

⚙️ Konfigurasi Git

Set username dan email (gunakan email GitHub kamu)

git config --global user.name "Nama Kamu"
git config --global user.email "email@kamu.com"

🚀 Membuat Project Android dengan Git

1

Buat Project Android Baru

File → New → New Project → Empty Activity

2

Initialize Git Repository

VCS → Create Git Repository → OK (atau git init di terminal)

3

Buat File .gitignore

Android Studio otomatis membuat .gitignore untuk project Android

4

Add Files to Git

VCS → Git → Add (atau Ctrl+Alt+A, atau git add .)

5

First Commit

VCS → Commit → Tulis pesan "Initial commit" → Commit

6

Connect to GitHub

VCS → Git → Push → Define Remote → Masukkan URL GitHub repository

📄 File .gitignore untuk Android

🚫 File yang Tidak Perlu di-Track:

# Build files
/build/
/app/build/

# IDE files
.idea/
*.iml

# Local files
local.properties
.gradle/

# OS files
.DS_Store
Thumbs.db

Mengapa penting? File-file ini adalah hasil build atau konfigurasi lokal yang tidak perlu dibagikan ke tim. Menyimpannya di Git akan membuat repository besar dan menyebabkan konflik.

🌿 Branching Strategy

🎯 Mengapa Perlu Branch?

  • ✅ Eksperimen fitur baru tanpa merusak kode utama
  • ✅ Bekerja paralel dengan tim tanpa konflik
  • ✅ Isolasi bug fixes dari development
  • ✅ Code review sebelum merge ke main branch
  • ✅ Rollback mudah jika ada masalah

🌳 Branch Strategy untuk Android:

🏠
main/master

Kode production-ready, selalu stabil, siap release ke Play Store

🚧
develop

Development branch, integrasi fitur baru sebelum ke main

⭐
feature/nama-fitur

Branch untuk mengembangkan fitur spesifik (contoh: feature/login-screen)

🐛
hotfix/nama-bug

Branch untuk perbaikan bug urgent di production

⚠️ Mengatasi Merge Conflict

Merge conflict terjadi ketika dua branch mengubah baris kode yang sama. Berikut cara mengatasinya:

  1. 1. Git akan menandai file yang konflik dengan marker <<<<<<< dan >>>>>>>
  2. 2. Buka file di Android Studio, pilih perubahan yang ingin dipertahankan
  3. 3. Hapus marker conflict (<<<<<<<, =======, >>>>>>>)
  4. 4. Test kode untuk memastikan masih berfungsi
  5. 5. git add . → git commit -m "Resolve merge conflict"

Tugas Praktik

Saatnya praktik langsung dengan GitHub!

🎯 Tugas 1: Setup GitHub & First Repository

📋 Yang Harus Dilakukan:

  1. Buat akun GitHub dengan username yang profesional
  2. Setup profile GitHub (foto, bio, lokasi)
  3. Install Git di komputer kamu
  4. Konfigurasi Git dengan nama dan email
  5. Buat repository baru bernama "my-first-android-project"
  6. Clone repository ke komputer
  7. Buat file README.md dengan deskripsi project
  8. Commit dan push ke GitHub

📤 Yang Harus Dikumpulkan:

  • • Screenshot profil GitHub kamu
  • • Link repository "my-first-android-project"
  • • Screenshot terminal/command prompt saat konfigurasi Git

📱 Tugas 2: Android Project dengan Git

📋 Yang Harus Dilakukan:

  1. Buat project Android Studio baru (aplikasi kalkulator sederhana)
  2. Initialize Git repository di project tersebut
  3. Buat file .gitignore yang sesuai untuk Android
  4. Buat initial commit dengan pesan "Initial commit: Basic calculator app"
  5. Tambahkan fitur penjumlahan (buat branch feature/addition)
  6. Commit perubahan dengan pesan yang jelas
  7. Merge branch feature/addition ke main
  8. Push semua ke GitHub repository baru bernama "calculator-android"

📤 Yang Harus Dikumpulkan:

  • • Link repository "calculator-android" di GitHub
  • • Screenshot aplikasi kalkulator yang berjalan
  • • Screenshot commit history di GitHub
  • • File .gitignore yang kamu buat
