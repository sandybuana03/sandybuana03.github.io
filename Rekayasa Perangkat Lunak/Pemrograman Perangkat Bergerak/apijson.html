📚 Pengenalan RESTful API & JSON

🌐 Apa itu API?

API (Application Programming Interface) adalah seperti menu di restoran. Menu memberitahu kalian apa saja yang bisa dipesan, bagaimana cara memesannya, dan apa yang akan kalian dapatkan.

🍕 Analogi Restoran

Kalian (Client) → Pelayan (API) → Dapur (Server)

Kalian pesan makanan → Pelayan catat pesanan → Dapur masak → Pelayan antar makanan

🔗 Mengapa RESTful API?

REST (Representational State Transfer) adalah aturan main yang membuat API mudah digunakan dan dipahami. Seperti aturan lalu lintas yang membuat semua orang bisa berkendara dengan aman!

  • 🎯 Simple: Mudah dipahami dan digunakan
  • ⚡ Fast: Performa yang cepat
  • 🔄 Scalable: Bisa menangani banyak pengguna
  • 🌍 Universal: Bisa digunakan di berbagai platform

📱 Dalam Konteks Android

Aplikasi Android menggunakan RESTful API untuk:

  • 📥 Mengambil data dari server (seperti daftar produk)
  • 📤 Mengirim data ke server (seperti data registrasi)
  • ✏️ Mengupdate data (seperti edit profil)
  • 🗑️ Menghapus data (seperti hapus postingan)

🔗 Memahami REST API

🏗️ Prinsip-Prinsip REST

1. 🎯 Stateless (Tanpa Status)

Setiap request berdiri sendiri, seperti setiap kali kalian pesan makanan, pelayan tidak ingat pesanan sebelumnya. Server tidak menyimpan informasi tentang client di antara request.

2. 📍 Resource-Based (Berbasis Sumber Daya)

Setiap URL menunjuk ke sumber daya tertentu:

/students → Semua siswa /students/123 → Siswa dengan ID 123 /students/123/grades → Nilai dari siswa 123 /classes → Semua kelas /classes/XII-RPL → Kelas XII RPL

3. 🔧 HTTP Methods

Menggunakan method HTTP untuk menentukan aksi:

  • GET: Ambil data 📥
  • POST: Buat data baru ➕
  • PUT: Update data lengkap ✏️
  • PATCH: Update data sebagian 🔧
  • DELETE: Hapus data 🗑️

4. 🌐 Client-Server Architecture

Pemisahan yang jelas antara client (aplikasi Android) dan server (API). Keduanya bisa dikembangkan secara independen.

5. 💾 Cacheable

Response dari server bisa di-cache untuk meningkatkan performa dan mengurangi beban server.

📄 Mengenal JSON

🤔 Apa itu JSON?

JSON (JavaScript Object Notation) adalah format untuk menyimpan dan mengirim data. Seperti kotak makan siang yang rapi - semua makanan tertata dengan label yang jelas!

📝 Struktur JSON

1. Object (Objek) 📦

{ "nama": "Budi", "umur": 17, "kelas": "XII RPL" }

2. Array (Daftar) 📋

[ "Matematika", "Bahasa Indonesia", "Pemrograman" ]

3. Kombinasi Object dan Array 🎯

{ "siswa": { "id": 1, "nama": "Sari Indah", "nis": "2024001", "umur": 16, "kelas": "XII RPL", "hobi": ["membaca", "coding", "gaming"], "alamat": { "jalan": "Jl. Pendidikan No. 45", "kota": "Bandung", "kodePos": "40123" } }, "nilai": [ {"mapel": "Matematika", "nilai": 85}, {"mapel": "Bahasa Indonesia", "nilai": 90}, {"mapel": "Pemrograman", "nilai": 95} ] }

✅ Aturan JSON

  • 🔤 String harus pakai tanda kutip ganda (")
  • 🔢 Number tidak perlu tanda kutip
  • ✅ Boolean: true atau false
  • 🚫 null untuk nilai kosong
  • 📦 Object pakai kurung kurawal { }
  • 📋 Array pakai kurung siku [ ]

🚫 Kesalahan Umum JSON

❌ Salah:

{ nama: 'Budi', // Tidak pakai tanda kutip 'umur': 17, // Pakai kutip tunggal kelas: "XII RPL", // Tidak konsisten }

✅ Benar:

{ "nama": "Budi", "umur": 17, "kelas": "XII RPL" }

🔧 HTTP Methods dalam Detail

📥 GET - Mengambil Data

Seperti membaca buku di perpustakaan - kalian hanya melihat, tidak mengubah isinya.

Contoh Penggunaan:

GET /api/students GET /api/students/123 GET /api/students?kelas=XII-RPL

➕ POST - Membuat Data Baru

Seperti menulis catatan baru di buku diary - menambah sesuatu yang belum ada.

Contoh Penggunaan:

POST /api/students Content-Type: application/json { "nama": "Andi", "kelas": "XII RPL", "umur": 17 }

✏️ PUT - Mengupdate Data

Seperti mengedit essay yang sudah ditulis - mengubah yang sudah ada.

Contoh Penggunaan:

PUT /api/students/123 Content-Type: application/json { "nama": "Andi Pratama", "kelas": "XII RPL", "umur": 18 }

🔧 PATCH - Update Sebagian Data

Seperti mengedit hanya bagian tertentu dari dokumen - hanya mengubah field yang diperlukan.

Contoh Penggunaan:

PATCH /api/students/123 Content-Type: application/json { "umur": 18 }

🗑️ DELETE - Menghapus Data

Seperti menghapus file di komputer - data hilang permanen.

Contoh Penggunaan:

DELETE /api/students/123

📊 Ringkasan HTTP Methods

Method Fungsi Analogi Contoh URL
GET Ambil data Membaca buku 📖 GET /api/students
POST Buat data baru Menulis catatan baru ✍️ POST /api/students
PUT Update data lengkap Tulis ulang halaman ✏️ PUT /api/students/123
PATCH Update sebagian data Edit bagian tertentu 🔧 PATCH /api/students/123
DELETE Hapus data Hapus file 🗑️ DELETE /api/students/123

// File: ApiClient.java package com.sekolah.siswaapi.api; import retrofit2.Retrofit; import retrofit2.converter.gson.GsonConverterFactory; import okhttp3.OkHttpClient; import okhttp3.logging.HttpLoggingInterceptor; public class ApiClient { // Base URL API - untuk testing bisa gunakan JSONPlaceholder // Contoh: "https://jsonplaceholder.typicode.com/" // Atau ganti dengan URL server kalian sendiri private static final String BASE_URL = "https://jsonplaceholder.typicode.com/"; private static Retrofit retrofit = null; public static Retrofit getClient() { if (retrofit == null) { // Logging interceptor untuk debug HttpLoggingInterceptor logging = new HttpLoggingInterceptor(); logging.setLevel(HttpLoggingInterceptor.Level.BODY); OkHttpClient client = new OkHttpClient.Builder() .addInterceptor(logging) .build(); retrofit = new Retrofit.Builder() .baseUrl(BASE_URL) .client(client) .addConverterFactory(GsonConverterFactory.create()) .build(); } return retrofit; } }

💡 Tips Best Practices

  • 🔄 Error Handling: Selalu handle error dengan baik dan berikan pesan yang user-friendly
  • ⏳ Loading State: Tampilkan loading indicator saat request berlangsung
  • 📱 Network Check: Cek koneksi internet sebelum melakukan API call
  • 💾 Caching: Cache data untuk offline mode dan performa yang lebih baik
  • 🔒 Security: Gunakan HTTPS untuk keamanan data
  • ⚡ Threading: Retrofit otomatis menggunakan background thread
  • 🔑 Authentication: Implementasikan token-based authentication jika diperlukan
  • 📊 Logging: Gunakan logging interceptor untuk debugging (hanya di development)
  • ⏱️ Timeout: Set timeout yang reasonable untuk request
  • 🔄 Retry Logic: Implementasikan retry untuk request yang gagal

🚨 Common Errors & Solutions

❌ Network Error

Penyebab: Tidak ada koneksi internet atau server down

Solusi: Cek koneksi, tampilkan pesan error yang jelas, berikan opsi retry

❌ 404 Not Found

Penyebab: Endpoint tidak ditemukan atau ID tidak valid

Solusi: Validasi input, cek URL endpoint, handle response code

❌ 500 Internal Server Error

Penyebab: Error di sisi server

Solusi: Tampilkan pesan "Server sedang bermasalah", coba lagi nanti

❌ JSON Parsing Error

Penyebab: Format JSON tidak sesuai dengan model class

Solusi: Periksa struktur JSON, sesuaikan model class, gunakan @SerializedName

🎯 Tugas 2: Desain JSON

Buatlah struktur JSON untuk sistem informasi siswa dengan ketentuan:

  • Data siswa: nama, NIS, kelas, umur, alamat
  • Data nilai: mata pelajaran dan nilai
  • Data ekstrakurikuler yang diikuti
  • Buat untuk minimal 3 siswa dalam format array

Contoh Format:

{ "siswa": [ { "nama": "...", "nis": "...", // lengkapi struktur JSON } ] }
