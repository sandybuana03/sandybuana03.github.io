Pengenalan Permission & Layanan Perangkat

🔒 Apa itu Permission?

Permission (izin) adalah sistem keamanan Android yang melindungi data pribadi dan sumber daya perangkat pengguna. Bayangkan permission seperti "kunci pintu" - aplikasi harus meminta kunci untuk masuk ke "ruangan" tertentu di HP kalian. Sistem ini mulai diperkenalkan sejak Android 6.0 (API level 23) dengan konsep Runtime Permission.

Contoh: Aplikasi kamera butuh permission CAMERA untuk mengakses kamera HP, aplikasi maps butuh permission ACCESS_FINE_LOCATION untuk mengetahui lokasi presisi tinggi kalian.

📱 Mengapa Permission Penting?

🛡️

Keamanan

Melindungi data pribadi dari aplikasi jahat

🔐

Privasi

⚖️

Transparansi

Pengguna tahu apa yang diakses aplikasi

🎯

Kontrol

Bisa mengizinkan atau menolak akses

Permission Dasar Android

📋 Manifest Permission

Semua permission harus dideklarasikan di file AndroidManifest.xml. Ini seperti "daftar keinginan" aplikasi kalian - apa saja yang ingin diakses.

AndroidManifest.xml 
1  <uses-permission android:name="android.permission.CAMERA" />
2  <uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />
3  <uses-permission android:name="android.permission.RECORD_AUDIO" />

⚡ Jenis Permission

🟢

Normal Permission

Otomatis diberikan, tidak berbahaya

• INTERNET

• ACCESS_NETWORK_STATE

• VIBRATE

🔴

Dangerous Permission

Harus minta izin pengguna

• CAMERA

• ACCESS_FINE_LOCATION

• RECORD_AUDIO

Runtime Permission

🔄 Apa itu Runtime Permission?

Runtime Permission adalah sistem dimana aplikasi meminta izin saat dibutuhkan, bukan saat install. Ini seperti meminta izin pinjam motor saat mau pergi, bukan saat pertama ketemu! 😄

Keuntungan:

  • • Pengguna lebih nyaman (tidak bingung saat install)
  • • Konteks yang jelas (tahu kenapa butuh izin)
  • • Keamanan lebih baik

📝 Langkah-langkah Implementasi

1

Cek Permission

Periksa apakah aplikasi sudah punya izin

2

Request Permission

Minta izin jika belum ada

3

Handle Response

Tangani jawaban pengguna (izinkan/tolak)

💻 Contoh Code Sederhana

MainActivity.java 
 1  // 1. Cek permission
 2  if (ContextCompat.checkSelfPermission(this, 
 3      Manifest.permission.CAMERA) != PackageManager.PERMISSION_GRANTED) {
 4      
 5      // 2. Minta permission
 6      ActivityCompat.requestPermissions(this,
 7          new String[]{Manifest.permission.CAMERA}, REQUEST_CAMERA_PERMISSION);
 8  }
 9  
10  // 3. Handle response
11  @Override
12  public void onRequestPermissionsResult(int requestCode, String[] permissions, int[] grantResults) {
13      if (requestCode == REQUEST_CAMERA_PERMISSION) {
14          if (grantResults.length > 0 && grantResults[0] == PackageManager.PERMISSION_GRANTED) {
15              // Permission diberikan, buka kamera
16              openCamera();
17          } else {
18              // Permission ditolak, tampilkan pesan
19              showPermissionDeniedMessage();
20          }
21      }
22  }

Penjelasan: Code ini mengecek permission kamera, meminta izin jika belum ada, dan menangani respons pengguna dengan callback onRequestPermissionsResult().

Layanan Lokasi Android

🗺️ Jenis-jenis Location Permission

🎯

ACCESS_FINE_LOCATION

Lokasi presisi tinggi (GPS)

• Akurasi: ~3-5 meter

• Sumber: GPS, Network, Passive

• Baterai: Lebih boros

📡

ACCESS_COARSE_LOCATION

Lokasi perkiraan (Network)

• Akurasi: ~100-1000 meter

• Sumber: WiFi, Cell Tower

• Baterai: Lebih hemat

⚙️ Cara Menggunakan Location Service

1. Tambah Permission di Manifest

AndroidManifest.xml 
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />

2. Request Runtime Permission

Minta izin saat aplikasi butuh lokasi

3. Gunakan LocationManager atau FusedLocationProvider

API untuk mendapatkan koordinat lokasi

💡 Tips Best Practice

🔋

Hemat Baterai

  • • Gunakan COARSE jika tidak butuh presisi
  • • Stop location update saat tidak perlu
  • • Set interval yang wajar (minimal 5 detik)
  • • Gunakan FusedLocationProvider untuk efisiensi
👤

User Experience

  • • Jelaskan kenapa butuh lokasi dengan jelas
  • • Berikan alternatif jika ditolak
  • • Tampilkan loading saat mencari lokasi
  • • Handle error dengan graceful

🆕 Update Android 13+ (API 33+)

Perubahan Permission Terbaru:

  • • Notification Permission: Butuh permission POST_NOTIFICATIONS
  • • Media Permission: READ_MEDIA_IMAGES, READ_MEDIA_VIDEO, READ_MEDIA_AUDIO
  • • Granular Location: Approximate location sebagai default
  • • Runtime Permission: Lebih ketat untuk sensitive permissions

Layanan Kamera Android

📷 Permission Kamera

CAMERA Permission

Izin untuk mengakses kamera perangkat (Dangerous Permission)

AndroidManifest.xml 
1  <uses-permission android:name="android.permission.CAMERA" />
2  <uses-feature android:name="android.hardware.camera" android:required="true" />

Permission Tambahan

📹 RECORD_AUDIO

Untuk merekam video dengan suara

💾 Storage Permission

• Android 10+: Scoped Storage (tidak butuh permission)
• Android 9 ke bawah: WRITE_EXTERNAL_STORAGE

📱 Camera Hardware

Deklarasi uses-feature untuk filter di Play Store

🔧 Cara Menggunakan Kamera

1

Intent Kamera (Mudah)

Menggunakan aplikasi kamera bawaan

MainActivity.java 
1  // Untuk foto
2  Intent intent = new Intent(MediaStore.ACTION_IMAGE_CAPTURE);
3  startActivityForResult(intent, REQUEST_CAMERA);
4  
5  // Untuk video
6  Intent intent = new Intent(MediaStore.ACTION_VIDEO_CAPTURE);
7  startActivityForResult(intent, REQUEST_VIDEO);
2

Camera API (Advanced)

Kontrol penuh atas kamera

  • • Custom UI kamera
  • • Kontrol fokus, zoom, flash
  • • Real-time preview

Best Practices Permission

👤 User Experience (UX) Terbaik

💬

Jelaskan Alasan

Beri tahu pengguna kenapa aplikasi butuh permission tertentu sebelum meminta izin.

⏰

Minta Saat Dibutuhkan

Jangan minta semua permission di awal. Minta saat fitur akan digunakan.

🔄

Berikan Alternatif

Sediakan cara lain jika pengguna menolak permission.

🎯

Konteks yang Jelas

Minta permission dalam konteks yang masuk akal.

🔒 Keamanan & Privasi

Prinsip Least Privilege

Minta permission minimal yang dibutuhkan

✅ Baik: Minta COARSE_LOCATION untuk weather app
❌ Buruk: Minta FINE_LOCATION untuk weather app

Data Minimization

Ambil dan simpan data sesedikit mungkin

Transparansi

Buat privacy policy yang jelas dan mudah dipahami

⚡ Performance & Battery

🔋

Hemat Baterai

  • • Stop location updates saat tidak perlu
  • • Gunakan interval yang wajar
  • • Pilih accuracy yang sesuai
📱

Resource Management

  • • Release camera saat tidak digunakan
  • • Handle lifecycle dengan benar
  • • Avoid memory leaks

🎯 Contoh Dialog Permission yang Baik

❌ Contoh Buruk

"Aplikasi ini membutuhkan akses kamera."

✅ Contoh Baik

"Untuk mengambil foto profil, aplikasi ini perlu akses ke kamera. Foto hanya disimpan di perangkat Anda dan tidak dibagikan ke server manapun."

🔄 Handling Permission Rationale

shouldShowRequestPermissionRationale()

Method ini membantu menentukan apakah perlu menampilkan penjelasan tambahan kepada pengguna:

  • • true: Pengguna pernah menolak, tapi belum pilih "Don't ask again"
  • • false: Pertama kali minta atau pengguna pilih "Don't ask again"
  • • Gunakan untuk menampilkan dialog penjelasan sebelum minta permission
