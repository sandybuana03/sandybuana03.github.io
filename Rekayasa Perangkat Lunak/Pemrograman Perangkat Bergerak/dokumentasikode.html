☕ Javadoc Basics

🤔 Apa itu Javadoc?

Javadoc adalah tool bawaan Java untuk membuat dokumentasi dari komentar khusus dalam kode. Javadoc menggunakan format komentar /** */.

📝 Syntax Dasar Javadoc

/** * Deskripsi singkat tentang method/class * * Deskripsi detail (opsional) * * @param namaParameter deskripsi parameter * @return deskripsi nilai yang dikembalikan * @throws ExceptionType kondisi kapan exception terjadi * @author nama pembuat * @since versi kapan ditambahkan */

🏷️ Tag-tag Penting dalam Javadoc

  • @param - Menjelaskan parameter method
  • @return - Menjelaskan nilai yang dikembalikan
  • @throws/@exception - Menjelaskan exception yang mungkin terjadi
  • @author - Nama pembuat
  • @since - Versi kapan ditambahkan
  • @deprecated - Menandai kode yang sudah usang

💻 Contoh Praktis: Class Android

/** * Activity untuk menampilkan profil pengguna * * Activity ini menangani tampilan profil pengguna termasuk * foto profil, nama, email, dan informasi lainnya. * * @author Tim Android SMK * @since 1.0 */ public class ProfileActivity extends AppCompatActivity { /** * Memuat data profil pengguna dari database * * @param userId ID unik pengguna yang akan dimuat * @return User object yang berisi data pengguna * @throws UserNotFoundException jika user tidak ditemukan */ public User loadUserProfile(String userId) throws UserNotFoundException { // implementasi method return user; } }

🎯 KDoc untuk Kotlin

🚀 Apa itu KDoc?

KDoc adalah sistem dokumentasi untuk Kotlin yang mirip dengan Javadoc, tapi dengan syntax yang lebih modern dan fleksibel!

📝 Syntax KDoc

/** * Deskripsi singkat tentang function/class * * Deskripsi detail yang lebih panjang jika diperlukan. * Bisa menggunakan **markdown** untuk formatting! * * @param namaParameter deskripsi parameter * @return deskripsi nilai yang dikembalikan * @throws ExceptionType kondisi exception * @author nama pembuat * @since versi * @sample contoh penggunaan */

✨ Keunggulan KDoc

  • 📝 Markdown support - bisa pakai **bold**, *italic*, dll
  • 🔗 Link references - bisa link ke class/method lain
  • 📋 @sample tag - bisa include contoh kode
  • 🎯 Null safety - dokumentasi untuk nullable types

💻 Contoh KDoc untuk Android Kotlin

/** * Fragment untuk menampilkan daftar produk * * Fragment ini menampilkan daftar produk dalam **RecyclerView** * dengan fitur search dan filter berdasarkan kategori. * * @author Tim Android SMK * @since 2.0 * @sample sampleUsage */ class ProductListFragment : Fragment() { /** * Memfilter daftar produk berdasarkan query pencarian * * @param query string pencarian, bisa null atau empty * @param category kategori produk untuk filter tambahan * @return List produk yang sudah difilter, tidak akan null * @throws IllegalArgumentException jika category tidak valid */ fun filterProducts( query: String?, category: ProductCategory ): List<Product> { // implementasi return filteredProducts } } /** * Contoh penggunaan ProductListFragment */ fun sampleUsage() { val fragment = ProductListFragment() val products = fragment.filterProducts("smartphone", ProductCategory.ELECTRONICS) }

🔗 Link References dalam KDoc

/** * Mengirim data ke server menggunakan [ApiService] * * Method ini akan memanggil [ApiService.sendData] dan * menangani response dalam [handleResponse]. * * @see ApiService * @see handleResponse */ fun sendToServer(data: UserData) { // implementasi }

🎯 Best Practices Dokumentasi

✅ DO - Lakukan Ini:

  • 📝 Tulis deskripsi yang jelas dan singkat
  • 🎯 Jelaskan tujuan, bukan implementasi
  • 📋 Dokumentasikan semua parameter dan return value
  • ⚠️ Sebutkan exception yang mungkin terjadi
  • 💡 Berikan contoh penggunaan jika perlu

❌ DON'T - Jangan Lakukan:

  • 🚫 Dokumentasi yang terlalu panjang dan bertele-tele
  • 🚫 Mengulangi nama method dalam deskripsi
  • 🚫 Dokumentasi yang tidak up-to-date
  • 🚫 Menggunakan bahasa yang terlalu teknis

📱 Contoh Dokumentasi Activity Android

/** * Activity utama untuk login pengguna * * Menangani proses autentikasi pengguna melalui email/password * atau login dengan Google. Setelah berhasil login, akan * redirect ke MainActivity. * * @author Tim Development * @since 1.0 */ class LoginActivity : AppCompatActivity() { /** * Memvalidasi input email dan password * * @param email alamat email pengguna * @param password password pengguna (minimal 6 karakter) * @return true jika valid, false jika tidak * @throws IllegalArgumentException jika email format salah */ private fun validateInput(email: String, password: String): Boolean { // validasi email format if (!android.util.Patterns.EMAIL_ADDRESS.matcher(email).matches()) { throw IllegalArgumentException("Format email tidak valid") } // validasi password length return password.length >= 6 } /** * Melakukan proses login ke server * * @param credentials data login pengguna * @return LiveData yang berisi hasil login */ fun performLogin(credentials: LoginCredentials): LiveData<LoginResult> { // implementasi login return loginResult } }

🛠️ Tools & Generate Dokumentasi

🏭 Generate Dokumentasi Otomatis

Setelah menulis dokumentasi dalam kode, kita bisa generate menjadi website HTML yang cantik! 🌐

☕ Javadoc Tool

📋 Cara Generate Javadoc:

  1. Buka terminal/command prompt
  2. Navigate ke folder project
  3. Jalankan command: javadoc -d docs *.java
  4. Buka file docs/index.html di browser
# Command untuk generate Javadoc javadoc -d documentation -sourcepath src -subpackages com.myapp # Dengan custom options javadoc -d docs -author -version -use -windowtitle "My Android App" *.java

🎯 Dokka untuk Kotlin

Dokka adalah tool untuk generate dokumentasi dari KDoc. Lebih modern dan support Kotlin features!

// build.gradle (Module: app) plugins { id 'org.jetbrains.dokka' version '1.8.20' } // Generate dokumentasi ./gradlew dokkaHtml // Output akan ada di build/dokka/html/

🔧 Android Studio Integration

💡 Tips Android Studio:

  • 📝 Ketik /** di atas method → auto-generate template
  • 🔍 Hover mouse di method → lihat dokumentasi
  • ⚡ Ctrl+Q → quick documentation
  • 🎯 Tools → Generate JavaDoc → batch generate

📝 Tugas Praktik

🎯 Instruksi Tugas

Buatlah dokumentasi lengkap untuk aplikasi Android sederhana dengan ketentuan berikut:

📱 Tugas 1: Dokumentasi Activity (25 poin)

Buat dokumentasi untuk MainActivity yang memiliki fitur:

  • Menampilkan daftar kontak
  • Menambah kontak baru
  • Mencari kontak berdasarkan nama

Yang harus didokumentasikan:

  • Class description
  • Method untuk add contact
  • Method untuk search contact
  • Method untuk display contacts

🔄 Tugas 2: Dokumentasi Adapter (25 poin)

Buat dokumentasi untuk ContactAdapter dengan fitur:

  • Menampilkan nama dan nomor telepon
  • Click listener untuk edit kontak
  • Long click untuk delete kontak

Gunakan KDoc jika menggunakan Kotlin, atau Javadoc jika Java.

🛠️ Tugas 3: Dokumentasi Utility Class (25 poin)

Buat dokumentasi untuk ContactUtils class dengan method:

  • validatePhoneNumber(String phone)
  • formatPhoneNumber(String phone)
  • isValidEmail(String email)

Sertakan @param, @return, dan @throws untuk setiap method.

📚 Tugas 4: Generate Dokumentasi (25 poin)

Setelah selesai membuat dokumentasi:

  • Generate dokumentasi menggunakan Javadoc atau Dokka
  • Screenshot hasil dokumentasi HTML
  • Buat file README.md yang menjelaskan cara menjalankan generate dokumentasi

📋 Format Pengumpulan

  • 📁 Buat folder dengan nama: NamaKelas_NamaSiswa_DokumentasiKode
  • 📄 Sertakan file .java atau .kt dengan dokumentasi lengkap
  • 🖼️ Screenshot hasil generate dokumentasi
  • 📖 File README.md dengan penjelasan
  • ⏰ Deadline: 1 minggu dari hari ini

💡 Tips Pengerjaan

  • 🎯 Fokus pada kejelasan dan kelengkapan dokumentasi
  • 📝 Gunakan bahasa yang mudah dipahami
  • ✅ Pastikan semua parameter dan return value terdokumentasi
  • 🔍 Review dokumentasi sebelum dikumpulkan
  • ❓ Jangan ragu bertanya jika ada yang kurang jelas
