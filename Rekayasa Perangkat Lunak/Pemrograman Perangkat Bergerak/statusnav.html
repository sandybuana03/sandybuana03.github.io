Activity Lifecycle

Memahami siklus hidup Activity Android

📱 Apa itu Activity Lifecycle?

Activity Lifecycle adalah serangkaian tahapan yang dilalui sebuah Activity dari saat dibuat hingga dihancurkan. Seperti kehidupan manusia: lahir, tumbuh, dewasa, tua, dan meninggal.

🎯 Mengapa Penting?

  • • Menghemat battery: Pause operasi berat saat tidak terlihat
  • • Menjaga data: Simpan data penting sebelum Activity dihancurkan
  • • User experience: Aplikasi terasa responsif dan lancar

🔄 Tahapan Lifecycle

🌱

onCreate()

Kapan: Activity pertama kali dibuat

Fungsi: Inisialisasi komponen, setup layout dengan setContentView(), inisialisasi variabel

Yang TIDAK boleh: Operasi berat atau akses kamera/GPS

Analogi: Seperti bayi yang baru lahir, perlu setup dasar 👶

▶️

onStart()

Kapan: Activity mulai terlihat oleh user (tapi belum bisa diinteraksi)

Fungsi: Register broadcast receiver, mulai animasi UI

Catatan: Activity visible tapi belum di foreground

Analogi: Seperti bangun tidur, mata terbuka tapi belum siap beraktivitas 🌅

🎯

onResume()

Kapan: Activity di foreground dan siap berinteraksi dengan user

Fungsi: Mulai kamera, GPS, sensor, timer, animasi

Penting: Ini saat yang tepat untuk operasi yang butuh user interaction

Analogi: Seperti fokus penuh pada pekerjaan dan siap produktif 💪

⏸️

onPause()

Kapan: Activity kehilangan fokus (ada dialog, activity lain, atau multi-window)

Fungsi: Pause kamera/GPS, simpan draft data, pause animasi

Hati-hati: Method ini harus cepat (< 1 detik), jangan operasi berat

Analogi: Seperti istirahat sejenak saat ada gangguan ☕

⏹️

onStop()

Kapan: Activity tidak terlihat sama sekali (tertutup activity lain)

Fungsi: Stop semua operasi berat, unregister listener, release resource sementara

Catatan: Activity masih ada di memory, bisa di-restart

Analogi: Seperti tidur nyenyak, tidak sadar lingkungan 😴

🔄

onRestart()

Kapan: Activity kembali dari onStop() ke onStart() (user kembali ke app)

Fungsi: Refresh data, update UI yang mungkin berubah saat tidak terlihat

Catatan: Hanya dipanggil jika Activity di-restart, bukan dibuat baru

Analogi: Seperti bangun dari tidur dan melanjutkan aktivitas 🔄

💀

onDestroy()

Kapan: Activity akan dihancurkan (finish() dipanggil atau system butuh memory)

Fungsi: Cleanup final, release semua resource, unregister semua listener

Penting: Pastikan tidak ada memory leak di sini

Analogi: Seperti akhir kehidupan, semua harus dibersihkan 🕊️

Fragment Management

Mengelola Fragment untuk UI yang Fleksibel

🧩 Apa itu Fragment?

Fragment adalah bagian dari UI yang dapat digunakan kembali dalam Activity. Bayangkan seperti puzzle - satu Activity bisa terdiri dari beberapa Fragment yang bisa disusun ulang.

✅ Keuntungan Fragment

  • • Reusable: Bisa dipakai di berbagai Activity
  • • Modular: Kode lebih terorganisir
  • • Responsive: Mudah adaptasi untuk tablet/phone
  • • Dynamic: Bisa ditambah/hapus saat runtime

🎯 Kapan Menggunakan Fragment?

  • • Tab navigation (seperti Instagram)
  • • Master-detail layout (seperti email)
  • • Bottom navigation
  • • ViewPager (swipe antar halaman)

🔄 Fragment Lifecycle

Fragment punya lifecycle sendiri, mirip Activity tapi lebih kompleks:

🌱

onAttach() → onCreate() → onCreateView()

Fragment dibuat dan UI di-setup

▶️

onStart() → onResume()

Fragment aktif dan siap berinteraksi

💀

onPause() → onStop() → onDestroyView() → onDestroy() → onDetach()

Fragment dihancurkan dan dilepas dari Activity

Navigation Component

Navigasi Modern untuk Android

🗺️ Apa itu Navigation Component?

Navigation Component adalah library Android yang memudahkan implementasi navigasi dalam aplikasi. Seperti GPS untuk aplikasi - membantu user berpindah dengan mudah dan tidak tersesat!

🎯

Navigation Graph

Peta visual semua destinasi dalam aplikasi

🚀

NavController

Pengendali navigasi antar destinasi

📱

NavHost

Container untuk menampilkan destinasi

✨ Keuntungan Navigation Component

🔄

Automatic Back Stack Management

Otomatis mengelola tombol back, tidak perlu coding manual dengan FragmentTransaction

🎨

Built-in Animations

Animasi transisi yang smooth (slide, fade, dll) dan mudah dikustomisasi

📦

Safe Args

Passing data antar Fragment dengan type-safe, menghindari ClassCastException

🔗

Deep Link Support

Mudah handle link dari luar aplikasi (web, notifikasi, app lain)

🎯

Single Activity Architecture

Satu Activity dengan banyak Fragment, lebih efisien dan mudah dikelola

🛠️

Visual Navigation Editor

Editor visual di Android Studio untuk mendesain navigation flow

🏗️ Implementasi Navigation Component

Langkah-langkah Setup:

1

Tambah Dependencies

implementation "androidx.navigation:navigation-fragment-ktx"

2

Buat Navigation Graph

File XML yang mendefinisikan semua destinasi dan aksi navigasi

3

Setup NavHostFragment

Container di Activity untuk menampilkan Fragment

4

Navigasi dengan NavController

findNavController().navigate(R.id.action_to_destination)

State Management

Menyimpan dan Mengelola Data Aplikasi

💾 Mengapa State Management Penting?

Bayangkan kamu sedang mengisi form panjang, tiba-tiba HP diputar atau ada panggilan masuk. Tanpa state management yang baik, semua data yang sudah diketik akan hilang! 😱

❌ Tanpa State Management

  • • Data hilang saat rotasi layar
  • • Form kosong lagi setelah minimize
  • • User harus input ulang
  • • Experience buruk dan frustasi

✅ Dengan State Management

  • • Data tetap tersimpan
  • • Seamless user experience
  • • Aplikasi terasa professional
  • • User happy dan loyal

🛠️ Teknik State Management

📦 onSaveInstanceState()

  • • Kapan: Sebelum Activity di-pause/stop
  • • Untuk: Data kecil (primitives, strings)
  • • Limit: Maksimal ~1MB
  • • Restore: Di onCreate() atau onRestoreInstanceState()

💾 SharedPreferences

  • • Kapan: Data persisten (pengaturan)
  • • Untuk: Key-value pairs sederhana
  • • Keuntungan: Otomatis tersimpan
  • • Contoh: Username, theme, language

🏗️ ViewModel

  • • Kapan: Data UI yang kompleks
  • • Untuk: Survive configuration changes
  • • Keuntungan: Lifecycle-aware
  • • Contoh: List data, form state

🗄️ Room Database

  • • Kapan: Data besar dan kompleks
  • • Untuk: Penyimpanan lokal permanen
  • • Keuntungan: SQL dengan type safety
  • • Contoh: User data, cache, offline data

💡 Best Practices

🔄 Activity Lifecycle

  • • Jangan lakukan operasi berat di onPause() (< 1 detik)
  • • Selalu release resource di onDestroy()
  • • Gunakan onSaveInstanceState() untuk data penting
  • • Hindari memory leak dengan proper cleanup

🧩 Fragment Management

  • • Gunakan Navigation Component untuk navigasi
  • • Hindari nested Fragment yang terlalu dalam
  • • Selalu check isAdded() sebelum akses Activity
  • • Gunakan ViewModel untuk share data

💾 State Management

  • • Pilih teknik yang tepat sesuai kebutuhan
  • • Bundle untuk data kecil & sementara
  • • SharedPreferences untuk pengaturan
  • • ViewModel untuk data UI kompleks

🗺️ Navigation

  • • Gunakan Single Activity Architecture
  • • Manfaatkan Safe Args untuk type safety
  • • Setup proper deep links
  • • Test navigation flow secara menyeluruh
